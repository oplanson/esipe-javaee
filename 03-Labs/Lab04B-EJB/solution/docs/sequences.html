Diagrammes de séquence

Trois scénarios clés illustrant le comportement transactionnel des EJBs : transfert atomique CMT, traitement en lot avec bean Stateful et REQUIRES_NEW, et rapport planifié déclenché par le Timer Service.

SD1 — Transfert atomique entre comptes

ℹ️
Principe CMT REQUIRED : le débit et le crédit s'exécutent dans la même transaction gérée par le container. Toute exception provoque un rollback automatique des deux opérations.

SD2 — Traitement en lot (Bean Stateful)

ℹ️
Principe @Stateful + REQUIRES_NEW : chaque transfert du lot s'exécute dans sa propre transaction indépendante. Un transfert peut échouer sans annuler les autres. Le bean est détruit après @Remove.

SD3 — Rapport quotidien planifié (@Schedule)

ℹ️
Timer Service non-persistant : le timer @Schedule(hour="0", minute="0") se déclenche chaque jour à minuit. Il ne survit pas à un redémarrage du serveur (non-persistent).
