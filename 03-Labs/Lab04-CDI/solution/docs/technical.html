Architecture Technique

Présentation des couches applicatives, de la configuration CDI et des mécanismes de persistence. CDI 4.0 est le cœur du lab : chaque fonctionnalité est démontrée avec son cas d'usage réel dans l'application bancaire.

Couches applicatives

Fonctionnalités CDI — Tableau de référence

Annotation / Mécanisme Classes concernées Description
@ApplicationScoped ClientService, AccountService, BatchTransferService, BankingEventObserver, PremiumNotificationService, StandardNotificationService, EntityManagerProducer Singleton CDI — une seule instance partagée pour toute la durée de vie de l'application
@RequestScoped EntityManager (produit) Cycle de vie lié à la requête HTTP courante — évite les problèmes de concurrence sur l'EntityManager
@Produces EntityManagerProducer Factory CDI pour les types non-CDI nativement : EntityManager et Logger. Permet l'injection de types Jakarta EE standards.
@Qualifier — @Premium PremiumNotificationService Qualifier personnalisé — sélectionne l'implémentation "tous canaux" (Email+SMS+Push+InApp) pour les clients premium
@Qualifier — @Standard StandardNotificationService Qualifier personnalisé — sélectionne l'implémentation "email >1000€ uniquement" pour les clients standard
@Interceptor + @InterceptorBinding LoggingInterceptor + @Logged AOP déclaratif — trace entrée/sortie/durée/exception de toutes les méthodes portant @Logged
CDI Events — Event<T> ClientService, AccountService Producteurs d'événements : fire ClientCreatedEvent, AccountCreatedEvent, TransactionEvent
CDI Events — @Observes BankingEventObserver Observateur central — reçoit tous les événements et orchestre les notifications selon le type client
@Transactional (CMT) ClientService, AccountService Transaction Container-Managed — le container démarre/commit/rollback automatiquement. Rollback sur RuntimeException.
UserTransaction (BMT) BatchTransferService Transaction Bean-Managed — contrôle programmatique fin : utx.begin(), utx.commit(), utx.rollback(), timeout configurable

Producteurs CDI

La classe EntityManagerProducer expose des types non-CDI via @Produces :

@ApplicationScoped
public class EntityManagerProducer {

    @PersistenceUnit(unitName = "bankingPU")
    private EntityManagerFactory emf;

    @Produces
    @RequestScoped
    public EntityManager createEntityManager() {
        return emf.createEntityManager();
    }

    public void closeEntityManager(@Disposes EntityManager em) {
        if (em.isOpen()) em.close();
    }

    @Produces
    public Logger createLogger(InjectionPoint ip) {
        return Logger.getLogger(
            ip.getMember().getDeclaringClass().getName()
        );
    }
}

Intercepteur de logging

@Logged
@Interceptor
@Priority(Interceptor.Priority.APPLICATION)
public class LoggingInterceptor {

    @Inject
    private Logger logger;

    @AroundInvoke
    public Object logMethod(InvocationContext ctx) throws Exception {
        String method = ctx.getMethod().getName();
        long start = System.currentTimeMillis();
        logger.info("→ Entrée : " + method + " args=" + Arrays.toString(ctx.getParameters()));
        try {
            Object result = ctx.proceed();
            logger.info("← Sortie : " + method + " (" + (System.currentTimeMillis()-start) + "ms)");
            return result;
        } catch (Exception e) {
            logger.severe("✗ Exception : " + method + " — " + e.getMessage());
            throw e;
        }
    }
}

Gestion des transactions

CMT — Container-Managed Transactions

@Transactional

Utilisé par ClientService et AccountService. Le container Jakarta EE gère le cycle de vie transactionnel :

  • Début automatique avant la méthode
  • Commit automatique après succès
  • Rollback automatique sur RuntimeException
  • Propagation REQUIRED par défaut

BMT — Bean-Managed Transactions

UserTransaction

Utilisé par BatchTransferService. Contrôle programmatique explicite :

  • utx.begin() — début explicite
  • utx.commit() — commit en cas de succès
  • utx.rollback() — rollback en cas d'erreur
  • utx.setTransactionTimeout() — timeout configurable
