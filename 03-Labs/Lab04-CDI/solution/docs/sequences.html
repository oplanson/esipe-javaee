Diagrammes de Séquence

Trois scénarios clés illustrant les mécanismes CDI en action : événements, intercepteurs, transactions CMT et BMT.

SD1 — Création d'un client avec événement CDI

Ce scénario montre le flux complet d'une requête POST de création de client, depuis le navigateur jusqu'à l'envoi de notification via l'événement CDI ClientCreatedEvent. Le LoggingInterceptor trace chaque appel de méthode marquée @Logged.

SD2 — Transaction bancaire avec alerte montant élevé

Dépôt ou retrait sur un compte. Si le montant dépasse 10 000 €, un événement supplémentaire onLargeTransaction() est déclenché par BankingEventObserver pour générer une alerte de conformité.

SD3 — Traitement par lots de virements (BMT)

BatchTransferService utilise UserTransaction (Bean-Managed Transaction) pour un contrôle programmatique fin. Chaque opération individuelle de virement peut utiliser REQUIRES_NEW pour s'isoler. En cas d'erreur, utx.rollback() annule le lot entier.

⚠
BMT vs CMT — Le contrôle BMT via UserTransaction offre une flexibilité maximale mais exige une gestion rigoureuse des cas d'erreur. Pour la majorité des cas, préférer @Transactional (CMT).
