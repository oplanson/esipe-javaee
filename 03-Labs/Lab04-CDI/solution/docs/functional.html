Architecture Fonctionnelle

Organisation en 5 domaines fonctionnels. Les services sont des beans CDI @ApplicationScoped orchestrés par injection. Le pattern Strategy est utilisé pour les notifications ; le système d'événements CDI assure le découplage entre les services.

1. Gestion Clients

ClientService

@ApplicationScoped @Transactional

Service principal de gestion des clients. Injecte EntityManager, Logger et Event<ClientCreatedEvent>.

  • createClient() — persiste le client et fire ClientCreatedEvent
  • findById(), findAll() — requêtes JPQL
  • updateClient(), deleteClient()

Client @Entity

@Entity Agrégat DDD

Entité racine d'agrégat. Encapsule identité, coordonnées et préférence de notification (PREMIUM / STANDARD).

  • id, name, email, phone
  • notificationType — détermine le qualifier CDI utilisé

Account @Entity

@Entity

Entité compte bancaire. Applique les règles métier de dépôt/retrait au niveau de l'objet domaine.

  • deposit(amount) — valide montant positif
  • withdraw(amount) — valide solde suffisant
  • Type : CHECKING ou SAVINGS

2. Gestion Comptes

AccountService

@ApplicationScoped @Logged @Transactional

Orchestre les opérations sur les comptes. Annoté @Logged → toutes les méthodes sont interceptées par LoggingInterceptor.

  • deposit() / withdraw() / transfer()
  • Fire AccountCreatedEvent à la création
  • Fire TransactionEvent (DEPOSIT/WITHDRAWAL/TRANSFER) après chaque opération

BatchTransferService

@ApplicationScoped BMT UserTransaction

Traitement par lots de virements bancaires. Utilise UserTransaction injecté pour un contrôle fin des transactions (Bean-Managed Transaction).

  • processBatch(transfers) — démarre utx.begin(), itère les transferts, utx.commit() ou utx.rollback() sur erreur
  • Timeout configurable par lot

Services auxiliaires

@ApplicationScoped

TransactionComparisonService — compare CMT vs BMT pour démonstration pédagogique.

TimeoutTestService — teste les comportements de timeout de transaction.

3. Notifications — Pattern Strategy via CDI Qualifiers

Deux implémentations de NotificationService sélectionnées dynamiquement par qualifier CDI.

PremiumNotificationService

@ApplicationScoped @Premium

Implémentation premium : tous les canaux de notification activés.

  • 📧 Email
  • 📱 SMS
  • 🔔 Push notification
  • 📲 In-App notification

Sélectionnée lorsque le client a le type PREMIUM.

StandardNotificationService

@ApplicationScoped @Standard

Implémentation standard : Email uniquement, avec seuil de montant.

  • 📧 Email — seulement si montant > 1 000 €
  • Aucune notification pour les petites transactions

Sélectionnée lorsque le client a le type STANDARD.

4. Événements CDI

Flux d'événements CDI — Vue d'ensemble

ClientCreatedEvent

Event POJO

Déclenché par ClientService.createClient(). Transporte l'identifiant du client et son type de notification.

AccountCreatedEvent

Event POJO

Déclenché par AccountService.createAccount(). Notifie de la création d'un nouveau compte.

TransactionEvent

Event POJO

Déclenché après chaque opération. Type : DEPOSIT, WITHDRAWAL ou TRANSFER. Transporte le montant pour le seuil d'alerte.

BankingEventObserver

@ApplicationScoped @Observes

Observateur central. Résout le service de notification (@Premium ou @Standard) selon le type du client. Déclenche onLargeTransaction() si montant > 10 000 €.

5. Cross-cutting Concerns

EntityManagerProducer

@ApplicationScoped @Produces

Fabrique CDI exposant des types non-CDI nativement.

  • @Produces @RequestScoped EntityManager — un EM par requête HTTP, évite la concurrence
  • @Produces Logger — logger contextualisé par classe injectée

LoggingInterceptor

@Interceptor @AroundInvoke

Intercepteur AOP déclaratif. Activé par l'annotation @Logged sur tout bean ou méthode.

  • Log entrée (méthode + arguments)
  • Log sortie (valeur retour + durée ms)
  • Log exception avec stack trace

@Logged

@InterceptorBinding

Annotation personnalisée de liaison d'intercepteur. Peut être posée sur une classe entière ou sur une méthode spécifique.

@InterceptorBinding
@Retention(RUNTIME)
@Target({TYPE, METHOD})
public @interface Logged {}
