Vue Multi-Service

🛡️ MicroProfile Fault Tolerance

AnnotationConfigurationOù appliquéeComportement
@RegisterRestClient baseUri via MicroProfile Config Toutes les interfaces client REST Client HTTP typé auto-implémenté par MicroProfile
@Retry maxRetries=3, delay=1000ms Toutes les méthodes des REST clients 3 nouvelles tentatives avec 1 seconde d'attente entre chaque
@Timeout value=2000ms (Client Svc) / 3000–5000ms (Gateway) Toutes les méthodes des REST clients Exception levée si la réponse n'arrive pas dans le délai imparti
@CircuitBreaker requestVolumeThreshold=4, failureRatio=0.5, delay=5000ms, successThreshold=2 Toutes les méthodes des REST clients Coupe le circuit après 50% d'échecs sur 4+ requêtes ; attend 5s ; referme après 2 succès
@Fallback Méthode fallback dédiée par méthode Toutes les méthodes des REST clients Retourne une valeur par défaut sûre (liste vide, objet null-safe) — dégradation gracieuse
@Bulkhead value=10 BankingAggregationService uniquement Limite à 10 appels concurrents maximum vers le service d'agrégation

⬡ Pattern Hexagonal — par service

Modèle de domaine

POJO pur, sans annotation technique. Contient uniquement la logique métier. Indépendant du framework.

Ex: Client, Account avec méthodes deposit(), close()…

Service applicatif

@ApplicationScoped @Transactional — orchestre le domaine, délègue à un port.

Ex: ClientService, AccountService

Port (interface)

Interface Java pure. Ne contient aucune dépendance sur JPA ou une technologie spécifique.

Ex: ClientRepository, AccountRepository

Adaptateur JPA

Implémente le port. Utilise EntityManager Jakarta Persistence. Annoté @ApplicationScoped.

Ex: ClientRepositoryAdapter, AccountRepositoryAdapter

ℹ️
Database per Service — Chaque service possède sa propre base de données. Aucun accès SQL croisé n'est autorisé. Les données partagées transitent uniquement par API REST.
