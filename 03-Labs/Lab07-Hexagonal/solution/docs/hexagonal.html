Architecture Hexagonale

Le pattern Ports & Adapters (Alistair Cockburn, 2005) isole le cœur applicatif de toute technologie externe. Le domaine et les ports définissent les règles — les adaptateurs branchent les technologies.

✓
Bénéfice clé — Indépendance technologique : On peut remplacer REST→GraphQL, JPA→MongoDB, CDI→Kafka sans toucher à une seule ligne de domaine ou de service applicatif.

Diagramme Hexagonal Complet

Ports Primaires (Entrants — Port IN)

Interfaces définies dans la couche application (com.bank.application.port.in). Les adaptateurs primaires dépendent de ces interfaces — jamais des implémentations.

Interface (Port)Cas d'utilisation principauxAdaptateurs qui l'utilisent
AccountManagementUseCase openAccount, closeAccount, reactivateAccount, getAccount, listAccounts AccountRestAdapterV2, AccountRestAdapter (v1), AccountWebAdapter
ClientManagementUseCase createClient, updateClient, deleteClient, getClient, listClients, upgradeToPremium, downgradeFromPremium ClientRestAdapterV2, ClientRestAdapter (v1), ClientWebAdapter
MoneyOperationsUseCase deposit, withdraw, transfer AccountRestAdapterV2, AccountRestAdapter (v1)

Ports Secondaires (Sortants — Port OUT)

Interfaces définies dans la couche application (com.bank.application.port.out). Les adaptateurs secondaires implémentent ces interfaces — inversion de dépendance (DIP).

Interface (Port)Méthodes clésImplémentation(s)Technologie
AccountRepository findById, findByClientId, save, delete, existsByAccountNumber JpaAccountAdapter EclipseLink JPA + PostgreSQL
ClientRepository findById, findAll, save, delete, existsByEmail JpaClientAdapter EclipseLink JPA + PostgreSQL
EventPublisher publish(DomainEvent) CDIEventPublisherAdapter CDI 4.0 Event Bus (jakarta.enterprise.event.Event)

Exemples d'Indépendance Technologique

🔄 REST → GraphQL

Créer un nouvel adaptateur primaire GraphQL implémentant les mêmes ports use case. Zéro modification du domaine ou des services.

Port IN

🔄 JPA → MongoDB

Créer MongoAccountAdapter implements AccountRepository. Le domaine et les services n'en savent rien.

Port OUT

🔄 CDI Events → Kafka

Créer KafkaEventPublisherAdapter implements EventPublisher. Les agrégats continuent d'émettre des DomainEvent sans changement.

EventPublisher

🔄 Tests unitaires purs

Les services applicatifs et le domaine se testent avec des ports mockés — aucune base de données, aucun serveur nécessaire.

Testabilité
