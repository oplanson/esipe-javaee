Architecture Fonctionnelle

Organisation fonctionnelle de l'application selon le pattern Ports & Adapters : couche domaine pure, couche application (use cases), adaptateurs primaires (driving) et secondaires (driven).

Vue Hexagonale — Couches

1 · Couche Application — Cas d'Utilisation

AccountManagementService

Implémente AccountManagementUseCase. Orchestre les opérations de gestion des comptes bancaires.

MéthodeDescription
openAccount(OpenAccountCommand)Crée un nouveau compte pour un client existant.
closeAccount(accountId)Clôture un compte (solde 0 requis — R3).
reactivateAccount(accountId)Réactive un compte précédemment clôturé.
getAccount(accountId)Récupère un compte par identifiant → AccountDTO.
listAccounts(clientId)Liste tous les comptes d'un client → List<AccountDTO>.

ClientManagementService

Implémente ClientManagementUseCase. Gestion du cycle de vie client et statut premium.

MéthodeDescription
createClient(CreateClientCommand)Crée un client après vérification unicité email (R12).
updateClient(UpdateClientCommand)Met à jour les informations client.
deleteClient(clientId)Supprime un client du système.
getClient(clientId)Récupère un client par identifiant → ClientDTO.
listClients()Liste tous les clients → List<ClientDTO>.
upgradeToPremium(clientId)Passe un client en statut premium (frais transfert = 0).
downgradeFromPremium(clientId)Rétrograde un client premium au statut standard.

MoneyOperationsService

Implémente MoneyOperationsUseCase. Opérations financières sur les comptes.

MéthodeDescription
deposit(DepositCommand)Crédite un montant sur un compte actif → génère MoneyDepositedEvent.
withdraw(WithdrawCommand)Débite un compte actif si solde suffisant → génère MoneyWithdrawnEvent.
transfer(TransferCommand)Virement avec calcul de frais via TransferService → génère MoneyTransferredEvent.

2 · Domaine Pur

Agrégat Account

Racine d'agrégat principale. Encapsule l'état financier d'un compte bancaire et les invariants associés.

  • deposit(Money) — Crédite si compte actif (R1), devise cohérente (R4) → émet MoneyDepositedEvent
  • withdraw(Money) — Débite si compte actif (R1), solde suffisant (R2), devise cohérente (R4) → émet MoneyWithdrawnEvent
  • close() — Clôture si solde = 0 (R3) et compte actif (R1)
  • reactivate() — Réactive un compte clôturé
  • Accumule les événements de domaine pour publication différée (R11)
  • Garde active comme invariant central : toute opération financière vérifie ce flag

Agrégat Client

Racine d'agrégat client. Gère les informations personnelles, la liste des comptes et le statut premium.

  • updateInfo(name, Email) — Met à jour les informations personnelles
  • upgradeToPremium() — Valide que le client n'est pas déjà premium
  • downgradeFromPremium() — Valide que le client est bien premium
  • addAccount(accountId) — Associe un compte au client
  • Contient un Email value object (RFC 5322, unique — R7, R12)

TransferService (Service de Domaine)

Service de domaine coordonnant le transfert entre deux comptes. La logique de frais implique deux agrégats → justifie un service de domaine distinct.

  • Vérification même compte source/destination (garde-fou)
  • Vérification cohérence de devise (R4)
  • Calcul frais : client premium = gratuit ; client standard = 1% du montant, min 1€, max 50€ (R5)
  • Appelle from.withdraw(amount + fee) puis to.deposit(amount)

5 · Événements de Domaine

ℹ
Pattern : Les agrégats accumulent leurs événements en mémoire lors du traitement métier. Les services applicatifs publient ces événements après persistance via le port EventPublisher (R11).
ÉvénementÉmetteurDonnées
MoneyDepositedEventAccount.deposit()accountId, amount, currency, timestamp
MoneyWithdrawnEventAccount.withdraw()accountId, amount, currency, timestamp
MoneyTransferredEventAccount.withdraw() + Account.deposit()fromAccountId, toAccountId, amount, fee, currency, timestamp

La publication se fait via CDIEventPublisherAdapter qui implémente le port EventPublisher. Les observateurs CDI (@Observes) peuvent réagir aux événements sans couplage direct.
