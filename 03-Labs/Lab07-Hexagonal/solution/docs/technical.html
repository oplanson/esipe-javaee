Architecture Technique

Organisation technique des couches, règles de dépendances, objets-valeurs, commandes, versionnement API et configuration Open Liberty.

Schéma des Couches Techniques

Direction des Dépendances

ℹ
Principe de dépendance inversée : Le domaine ne dépend de rien. Les adaptateurs secondaires implémentent les ports définis dans la couche application — la dépendance pointe vers l'intérieur.
Couche sourceDirectionCouche cibleMécanisme
REST / Web Adapters→ dépend dePorts Primaires (interfaces use case)Injection CDI de l'interface
Services Applicatifs→ dépend deCouche Domaine + Ports SecondairesAppel direct domaine ; injection port secondaire
Adaptateurs Secondaires← implémententPorts SecondairesInversion de dépendance (DIP)
Domaine Pur✘ aucune dépendance—Java pur, pas de framework

Versionnement API

VersionClassesStatutNotes
V1 AccountRestAdapter · ClientRestAdapter @Deprecated — maintenu pour rétrocompatibilité Fonctionnalités de base uniquement
V2 AccountRestAdapterV2 · ClientRestAdapterV2 Courant — version recommandée Support premium, endpoints enrichis, meilleure validation
✓
Bénéfice hexagonal : V1 et V2 utilisent les mêmes ports et les mêmes services applicatifs. Seuls les adaptateurs changent. La migration vers V3 ne toucherait pas au domaine (R10).

Mappers

MapperTransformations
ClientMapperDomain Client ↔ JPA ClientEntity · Domain Client → ClientDTO
AccountMapperDomain Account ↔ JPA AccountEntity · Domain Account → AccountDTO

Les mappers garantissent que les entités JPA (avec annotations @Entity, @Column…) ne contaminent jamais le modèle de domaine pur.
