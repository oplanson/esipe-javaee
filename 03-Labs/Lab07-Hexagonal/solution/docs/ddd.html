1 · Agrégats (Aggregate Roots)

Un agrégat est une grappe d'entités et d'objets-valeurs traitée comme une unité de cohérence transactionnelle. La racine d'agrégat est le seul point d'entrée pour modifier l'état.

Account — Agrégat Compte

Aggregate Rootcom.bank.domain.model

État principal :

  • accountNumber : AccountNumber — identifiant métier IBAN-like
  • balance : Money — solde courant (immutable value object)
  • accountType : AccountType — CHECKING ou SAVINGS
  • active : boolean — invariant central de toutes les opérations
  • clientId : UUID — référence au client propriétaire

Comportements :

  • deposit(Money) — vérifie actif + devise, crédite, émet MoneyDepositedEvent
  • withdraw(Money) — vérifie actif + solde + devise, débite, émet MoneyWithdrawnEvent
  • close() — vérifie actif + solde=0, désactive
  • reactivate() — réactive le compte
  • getDomainEvents() — retourne les événements accumulés

Client — Agrégat Client

Aggregate Rootcom.bank.domain.model

État principal :

  • firstName, lastName : String — identité civile
  • email : Email — identifiant unique (value object)
  • premium : boolean — statut influençant les frais de transfert
  • accountIds : List<UUID> — références aux comptes

Comportements :

  • updateInfo(firstName, lastName, Email) — mise à jour informations
  • upgradeToPremium() — passage premium (valide pas déjà premium)
  • downgradeFromPremium() — rétrogradation (valide est bien premium)
  • addAccount(accountId) — association d'un compte

3 · Service de Domaine — TransferService

Domain Servicecom.bank.domain.service

Pourquoi un service de domaine et non une méthode dans l'agrégat ?

Le transfert implique deux agrégats distincts (Account source + Account destination) ainsi que l'état du Client pour le calcul des frais. Cette logique ne peut pas résider dans un seul agrégat sans en violer les frontières de cohérence.

Responsabilités :

  • Vérifie que les comptes source et destination sont différents
  • Vérifie la cohérence de devise entre les deux comptes
  • Calcule les frais selon le statut client :
    — Premium → frais = 0€
    — Standard → frais = max(1€, min(50€, montant × 1%))
  • Appelle from.withdraw(amount + fee)
  • Appelle to.deposit(amount)
  • Les deux agrégats émettent leurs événements de domaine
ℹ️
Pattern DDD : Le service de domaine est un objet sans état. Il orchestre les agrégats mais ne détient aucune donnée propre. Il est instancié et invoqué par le service applicatif MoneyOperationsService.

4 · Événements de Domaine

Les événements de domaine capturent les faits métier importants qui se sont produits dans le domaine. Ils permettent un couplage lâche entre le domaine et l'infrastructure.

ÉvénementÉmetteur (Agrégat)Données transportéesConsommateurs potentiels
MoneyDepositedEvent Account.deposit() accountId, amount, currency, newBalance, timestamp Audit, notification, analytics
MoneyWithdrawnEvent Account.withdraw() accountId, amount, currency, newBalance, timestamp Audit, alerte découvert, analytics
MoneyTransferredEvent Account.withdraw() + Account.deposit() (via TransferService) fromAccountId, toAccountId, amount, fee, currency, timestamp Audit, fraude, réconciliation

5 · Repositories comme Ports Secondaires

Conformément au DDD, les repositories sont définis comme des interfaces dans la couche application. Ils représentent des abstractions de persistance — pas des implémentations JPA.

Interface (Port)Package (Application)Implémentation (Infrastructure)Pourquoi séparé ?
AccountRepository com.bank.application.port.out JpaAccountAdapter
com.bank.infrastructure.persistence.adapter		 Le domaine ne dépend pas de JPA. Testable avec un mock en mémoire.
ClientRepository com.bank.application.port.out JpaClientAdapter
com.bank.infrastructure.persistence.adapter		 Séparation infrastructure/domaine. Remplacement JPA→MongoDB sans toucher le domaine.

6 · Langage Ubiquitaire

Le langage ubiquitaire est partagé entre les experts métier et les développeurs. Chaque terme est précisément défini et utilisé de manière cohérente dans le code et la documentation.

Terme métierClasse / Concept techniqueDéfinition métier
AccountAccount (agrégat)Compte bancaire appartenant à un client. Peut être CHECKING (courant) ou SAVINGS (épargne). A un solde et un statut actif/inactif.
ClientClient (agrégat)Personne physique titulaire de un ou plusieurs comptes. Peut avoir le statut premium.
MoneyMoney (value object)Montant monétaire immuable associé à une devise. Unité fondamentale des opérations financières.
Deposit (Dépôt)Account.deposit() + DepositCommandOpération créditant un montant sur un compte actif. Génère un MoneyDepositedEvent.
Withdrawal (Retrait)Account.withdraw() + WithdrawCommandOpération débitant un montant d'un compte actif avec vérification du solde disponible.
Transfer (Virement)TransferService + TransferCommandMouvement de fonds entre deux comptes. Soumis à des frais pour les clients standards.
PremiumClient.premiumStatut accordé à un client lui donnant des avantages (transferts gratuits). Modifiable via upgrade/downgrade.
AccountNumberAccountNumber (value object)Identifiant métier unique d'un compte. Format IBAN-like FR+27 chiffres. Généré automatiquement à l'ouverture.
Port (Entrant)Interface *UseCaseInterface définissant ce que l'application offre aux acteurs externes (API, UI).
Port (Sortant)Interface *Repository, EventPublisherInterface définissant ce que l'application attend des systèmes externes (base de données, messaging).
