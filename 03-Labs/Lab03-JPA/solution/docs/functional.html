Lab 03 / Architecture Fonctionnelle

Architecture Fonctionnelle

Vue d'ensemble des domaines métier, composants Jakarta EE, entités JPA et interactions applicatives de Banking JPA Application — Lab 03.

Flux applicatif global

1 · Gestion des Clients

ClientController

@WebServlet loadOnStartup=1

Servlet principale de gestion CRUD des clients. Mappée sur deux URL :

  • /clients — liste paginée (GET) et formulaire de création (POST)
  • /client — consultation, modification et suppression d'un client individuel

Le paramètre loadOnStartup=1 garantit l'initialisation avant toute requête.

ClientService

Singleton EntityManager RESOURCE_LOCAL

Service métier implémenté comme un Singleton Java (Singleton.getInstance()). Il gère directement le cycle de vie de l'EntityManager : création de l'EntityManagerFactory depuis l'unité bankingPU, ouverture/fermeture des transactions en mode RESOURCE_LOCAL (begin / commit / rollback explicites).

Entité Client

@Entity @Table(clients) @OneToMany
ÉlémentDétail
@Entity @Table("clients")Mappée sur la table SQL clients
@OneToMany(accounts)Relation comptes (orphanRemoval=true)
@NamedQueries x4Client.findAll, findById, findByEmail, countAll
@PrePersistInitialise la date de création
@PreUpdateMet à jour la date de modification

Entité Account

@Entity @Table(accounts) @ManyToOne
ÉlémentDétail
@Entity @Table("accounts")Mappée sur la table SQL accounts
@ManyToOne(client)Référence vers le client propriétaire
@NamedQueries x4Account.findAll, findById, findByClient, findByStatus
deposit(amount)Crédite le solde ; montant strictement positif
withdraw(amount)Débite le solde ; vérifie la suffisance du solde

2 · Validation des Transactions

TransactionValidatorServlet

@WebServlet(/validate-transaction) Content Negotiation

Valide les montants de transaction. Lit le paramètre amount, le compare au seuil JNDI (app/maxTransactionAmount, défaut 10 000 €) et retourne une réponse HTML ou JSON selon l'en-tête Accept.

JndiConfigService

@ApplicationScoped JNDI

Bean CDI de portée application réalisant les lookups JNDI :

  • app/maxTransactionAmount → 10 000
  • app/maxLoginAttempts → 3
  • app/supportEmail → adresse support configurable

3 · Migration & Configuration

DatabaseMigrationStartup

@WebListener ServletContextListener Flyway 10.4.1

Listener déclenché au démarrage. Exécute les migrations SQL versionées via Flyway. baselineOnMigrate=true autorise la migration sur une base existante.

ScriptContenu
V1__create_clients.sqlCréation de la table clients
V2__create_accounts.sqlCréation de la table accounts avec ON DELETE CASCADE
V3__add_status.sqlColonne status sur accounts

4 · Supervision MicroProfile

DatabaseHealthCheck

@Liveness

Sonde de vivacité. Exécute SELECT 1 sur la datasource pour vérifier la disponibilité de la base. Exposée sur /health/live.

WebAppReadinessCheck

@Readiness

Sonde de disponibilité. Vérifie que les migrations sont appliquées et le contexte initialisé. Exposée sur /health/ready.
