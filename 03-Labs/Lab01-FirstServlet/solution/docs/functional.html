Architecture Fonctionnelle

Description des fonctionnalités exposées aux utilisateurs, des parcours de navigation et du modèle de données géré par l'application.

Carte des fonctionnalités

F1

Page de bienvenue

Le servlet WelcomeServlet répond aux requêtes GET /welcome en générant dynamiquement une page HTML affichant la date et l'heure courante (Java LocalDateTime, formatée via DateTimeFormatter) ainsi que des liens de navigation vers l'accueil, la liste des clients et le formulaire d'ajout.

F2

Liste des clients

Le servlet ClientListServlet répond aux requêtes GET /clients en affichant une table HTML de tous les clients stockés en mémoire. Si le paramètre d'URL ?message=success est présent, une bannière de confirmation verte est affichée. Un lien permet d'accéder au formulaire d'ajout.

F3

Ajout d'un client

La page statique add-client.html propose un formulaire HTML avec validation JavaScript côté client. La soumission effectue un POST /clients. Le servlet valide les champs côté serveur, génère un nouvel ID, ajoute le client en mémoire et redirige (PRG) vers /clients?message=success. En cas d'erreur, il redirige vers /add-client.html?error=missing.

Modèle de données — Entité Client

AttributType JavaContrainte HTMLContrainte serveurDescription
id Long — Généré automatiquement : max(existants) + 1 Identifiant unique du client. Non soumis par l'utilisateur.
name String required, minlength="2", maxlength="100" Non null, non vide après trim() Nom complet du client. Valeur stockée après trim().
email String type="email", required, maxlength="100" Non null, non vide après trim() Adresse email. Validée par regex JS (/^[^\s@]+@[^\s@]+\.[^\s@]+$/) côté client.
phone String type="tel", required, maxlength="20" Non null, non vide après trim() Numéro de téléphone. Validé par regex JS (/^[\d\s\-\+\(\)]+$/) côté client.

La classe Client implémente Serializable (serialVersionUID = 1L), redéfinit equals() et hashCode() basés sur le champ id.

Acteurs du système

Navigateur utilisateur

Envoie des requêtes HTTP GET et POST. Exécute la validation JavaScript côté client sur le formulaire add-client.html. Affiche les réponses HTML générées par les servlets.

HTML5 JavaScript (ES6) CSS3

Serveur Open Liberty

Reçoit les requêtes HTTP, route vers WelcomeServlet ou ClientListServlet selon la configuration @WebServlet. Gère le cycle de vie des servlets, les erreurs HTTP et les sessions.

Open Liberty Servlet 6.0 Jakarta EE 10
⚠

Pas de persistance : Les données sont stockées uniquement en mémoire dans l'instance du servlet. Tout redémarrage ou rechargement de l'application efface les clients ajoutés. Aucune base de données n'est utilisée dans ce Lab 01.

ℹ

Absence de JSP/Thymeleaf : Les réponses HTML sont générées directement dans les servlets via PrintWriter. Les pages statiques (index.html, add-client.html) sont des fichiers servis directement par Open Liberty.
