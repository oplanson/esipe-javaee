Banking Application

Application web Jakarta EE de gestion de clients bancaires — premier servlet Jakarta EE déployé sur Open Liberty, exposant une interface CRUD en mémoire via des Servlets HTTP.

Java 17 Jakarta EE 10 Open Liberty Servlet 6.0 Maven 3 MicroProfile 6.0 Podman / Docker

Objectif

Illustrer les concepts de base des Servlets Jakarta EE : cycle de vie, gestion des requêtes GET/POST, réponses HTML dynamiques et pattern PRG (Post-Redirect-Get).

Auteur / Version

Auteur : Olivier Planson

Version : 1.0-SNAPSHOT

Contexte : ESIPE – Lab 01 – Jakarta EE & Microservices

Année : 2025

Endpoints de l'application

URLMéthode HTTPHandlerDescription
/GETindex.html (fichier statique)Page d'accueil — liens de navigation vers les fonctionnalités
/welcomeGETWelcomeServlet.doGet()Page de bienvenue — affiche la date/heure courante et des liens de navigation
/clientsGETClientListServlet.doGet()Liste tous les clients — lit le paramètre ?message=success pour la bannière
/clientsPOSTClientListServlet.doPost()Création d'un client — valide les champs, ajoute en mémoire, redirige (PRG)
/add-client.htmlGETFichier HTML statiqueFormulaire d'ajout de client avec validation côté client (JavaScript)
/error-404.html—Erreur déclarée dans web.xmlPage d'erreur 404 personnalisée
/error-500.html—Erreur déclarée dans web.xmlPage d'erreur 500 personnalisée
/healthGETMicroProfile HealthEndpoint de santé du serveur Open Liberty
/metricsGETMicroProfile MetricsMétriques de l'application et du JVM
/openapiGETMicroProfile OpenAPISpécification OpenAPI de l'API
ℹ

Stockage en mémoire : Les clients sont stockés dans une liste CopyOnWriteArrayList du servlet ClientListServlet. Toutes les données sont perdues au redémarrage du serveur. Ce design est volontaire pour ce Lab 01 d'introduction.
