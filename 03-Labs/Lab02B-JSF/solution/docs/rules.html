Règles de Gestion

10 règles de gestion numérotées R1–R10, couvrant la validation des données, les scopes CDI, la gestion de session et les règles UX de l'application Banking JSF.

ℹ
Convention de criticité : les règles critiques bloquent la soumission du formulaire si violées. Les règles importantes affectent le comportement. Les règles sans marquage sont des comportements attendus.

Validation des données client

R1 Critique
Nom client obligatoire — longueur 2 à 100 caractères
Le champ nom est requis (required="true") et sa longueur est contrainte entre 2 et 100 caractères via <f:validateLength minimum="2" maximum="100"/>. Toute violation lève un FacesMessage de type SEVERITY_ERROR et empêche la progression vers la phase Update Model Values.
Source : WEB-INF/views/client-form.xhtml — f:validateLength + required=true
R2 Critique
Format d'adresse email valide
L'adresse email est validée par le validateur personnalisé EmailValidator annoté @FacesValidator("emailValidator"). Le regex utilisé est : ^[A-Za-z0-9+_.-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}$. En cas d'échec, un message d'erreur localisé est ajouté au contexte JSF.
Source : com/bank/validator/EmailValidator.java — @FacesValidator
R3 Critique
Email requis
Le champ email ne peut pas être vide. L'attribut required="true" sur le composant h:inputText déclenche une validation JSF avant même l'appel au validateur personnalisé.
Source : WEB-INF/views/client-form.xhtml — attribut required="true"

Validation de l'adresse postale

R4 Critique
Adresse postale complète obligatoire
Les quatre champs de l'adresse sont requis : rue, ville, code postal et pays. Chaque champ porte l'attribut required="true" dans le formulaire. L'objet Address est un value object imbriqué dans Client.
Source : WEB-INF/views/client-form.xhtml — quatre champs required="true"
R5
Code postal — longueur 4 à 10 caractères
Le code postal doit comporter entre 4 et 10 caractères pour accepter les formats internationaux (FR 5 chiffres, UK alphanumérique, etc.). Contrôlé par <f:validateLength minimum="4" maximum="10"/>.
Source : WEB-INF/views/client-form.xhtml — f:validateLength sur le champ CP

Recherche et navigation

R6
Recherche insensible à la casse sur nom OU email
La méthode ClientService.searchClients(String term) convertit le terme de recherche et les valeurs en minuscules avant comparaison (toLowerCase().contains(...)). La recherche porte simultanément sur le nom complet et l'adresse email du client.
Source : com/bank/service/ClientService.java — méthode searchClients()

Architecture CDI et scopes

R7 CDI
ClientBean @SessionScoped — état maintenu entre les requêtes
ClientBean est annoté @Named @SessionScoped : une instance est créée par session HTTP et survit à plusieurs requêtes. Cela permet de mémoriser le client en cours d'édition, les résultats de recherche et les messages de confirmation entre les redirections. L'instance est détruite à l'expiration ou invalidation de la session.
Source : com/bank/beans/ClientBean.java — annotation CDI @SessionScoped
R8 CDI
ClientService @ApplicationScoped — singleton partagé entre toutes les sessions
ClientService est annoté @ApplicationScoped : une unique instance existe pour toute la durée de vie de l'application. Elle est partagée entre toutes les sessions et tous les threads. Le stockage ArrayList<Client> en mémoire est donc commun à tous les utilisateurs connectés simultanément.
Source : com/bank/service/ClientService.java — annotation CDI @ApplicationScoped

Expérience utilisateur

R9 UX
Confirmation obligatoire avant suppression d'un client
La suppression d'un client depuis la liste ne s'exécute qu'après confirmation de l'utilisateur. Un dialogue de confirmation JavaScript (onclick="return confirm(...)") est affiché au clic du bouton Supprimer. Si l'utilisateur annule, aucune requête n'est envoyée au serveur.
Source : WEB-INF/views/client-list.xhtml — attribut onclick sur le commandButton
R10 Session
Timeout de session : 30 minutes
La session HTTP expire automatiquement après 30 minutes d'inactivité. À l'expiration, le bean @SessionScoped ClientBean est détruit et le contexte de navigation est perdu. L'utilisateur est redirigé vers la page de démarrage.
Source : WEB-INF/web.xml — balise <session-timeout>30</session-timeout>
