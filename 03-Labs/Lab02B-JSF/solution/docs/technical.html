Architecture Technique

Vue technique de l'application : couches logicielles, APIs Jakarta EE utilisées, configuration spécifique JSF et structure du déployable WAR.

Diagramme des couches logicielles

APIs Jakarta EE & MicroProfile

APIVersionUsage dans l'application
jakarta.faces4.0 Moteur MVC principal — FacesServlet, Facelets, composants UI standard (h:, f:), Expression Language, cycle de vie en 6 phases.
jakarta.servlet6.0 Transport HTTP — FacesServlet délégue à Servlet 6.0. Configuration via web.xml. Gestion des sessions HTTP.
jakarta.enterprise.cdi4.0 Injection de dépendances — @Named, @SessionScoped, @ApplicationScoped, @Inject. Découverte automatique via beans.xml.
jakarta.servlet.jsp.jstl3.0 JSTL — tags c:forEach, c:if, c:choose utilisés en complément des composants JSF dans les vues Facelets.
microprofile-health4.0 Sondes @Liveness et @Readiness — découverte automatique par Open Liberty, exposées sur /health.
microprofile-config3.0 Injection de configuration via @ConfigProperty. Sources : microprofile-config.properties, variables d'environnement, propriétés système.

Configuration JSF — web.xml

Paramètre / MappingValeurRôle
Servlet mapping *.xhtml FacesServlet Toute requête vers un fichier .xhtml est traitée par JSF.
Servlet mapping /faces/* FacesServlet Mapping alternatif JSF (compatibilité).
Welcome file index.xhtml Page d'accueil par défaut de l'application.
javax.faces.PROJECT_STAGE Development Active les messages d'erreur détaillés JSF et les avertissements de développement.
Session timeout 30 minutes Expiration automatique de la session HTTP — libère le @SessionScoped ClientBean.

Configuration JSF — faces-config.xml

Règles de navigation

Navigation déclarative entre vues — outcome success, failure, cancel mappés vers les fichiers .xhtml cibles.

Localisation

Locale par défaut : en. Locale supportée : fr. Sélection automatique selon la langue du navigateur.

Resource Bundle

Bundle messages chargé depuis com/bank/messages.properties — accessible via EL #{msg.key} dans les vues.

Structure du déployable WAR

lab02b-jsf.war
├── index.xhtml                            ← Page d'accueil (welcome file)
├── WEB-INF/
│   ├── web.xml                            ← FacesServlet + session timeout + PROJECT_STAGE
│   ├── faces-config.xml                   ← Navigation, locale, resource bundle
│   ├── beans.xml                          ← Activation CDI (bean-discovery-mode="all")
│   ├── templates/
│   │   └── main.xhtml                     ← Template Facelets principal (header/nav/footer)
│   ├── views/
│   │   ├── client-list.xhtml              ← Liste des clients + recherche AJAX
│   │   ├── client-form.xhtml              ← Formulaire création/édition + validation
│   │   └── client-details.xhtml           ← Détail client + comptes
│   └── classes/
│       └── com/bank/
│           ├── beans/
│           │   └── ClientBean.java        ← @Named @SessionScoped
│           ├── service/
│           │   └── ClientService.java     ← @ApplicationScoped
│           ├── model/
│           │   ├── Client.java
│           │   ├── Account.java
│           │   └── Address.java
│           ├── validator/
│           │   └── EmailValidator.java    ← @FacesValidator
│           └── health/
│               ├── DatabaseHealthCheck.java   ← @Liveness
│               └── WebAppReadinessCheck.java  ← @Readiness
└── META-INF/
    └── MANIFEST.MF
ℹ
beans.xml — Obligatoire pour activer la découverte CDI 4.0 dans le WAR. Le mode bean-discovery-mode="all" permet l'injection sur toutes les classes sans annotation @Dependent explicite.
