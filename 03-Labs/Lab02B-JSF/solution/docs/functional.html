Architecture Fonctionnelle

Décomposition en domaines fonctionnels de l'application Banking JSF. Chaque domaine regroupe ses beans CDI, ses modèles et ses vues Facelets associées.

Diagramme de composants

Domaine 1 — Gestion des Clients

Ce domaine couvre le cycle de vie complet d'un client bancaire : création, listage, détail et recherche.

Beans CDI

BeanPortée CDIResponsabilité
ClientBean @Named @SessionScoped Contrôleur JSF — maintient l'état de la session (client sélectionné, résultats de recherche). Relaie les actions UI vers ClientService.
ClientService @ApplicationScoped Service métier singleton — stockage en mémoire (ArrayList), CRUD complet, recherche insensible à la casse.

Modèles

Client

Entité principale — identifiant auto-incrémenté, nom, prénom, email, objet Address imbriqué.

Account

Compte bancaire associé à un client — numéro de compte, solde, type (courant / épargne).

Address

Value object — rue, ville, code postal, pays. Validé dans le formulaire via f:validateLength.

Vues Facelets (WEB-INF/views/)

FichierRôleFonctionnalités clés
client-list.xhtml Liste des clients Tableau de données (h:dataTable), barre de recherche AJAX (f:ajax), bouton suppression avec confirmation.
client-form.xhtml Formulaire de création/édition Champs texte, f:validateLength, validateur email personnalisé, messages d'erreur h:message.
client-details.xhtml Détail d'un client Affichage complet : informations personnelles, adresse, liste des comptes associés.

Domaine 2 — Validation

ValidateurTypeRègle vérifiée
EmailValidator @FacesValidator Regex ^[A-Za-z0-9+_.-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}$ — rejet des adresses malformées avec message localisé.
f:validateLength Built-in JSF Longueur min/max sur le nom (2–100), code postal (4–10). Intégré directement dans les vues Facelets.
required="true" Built-in JSF Champs obligatoires : nom, email, rue, ville, code postal, pays.

Domaine 3 — Supervision (MicroProfile)

ClasseAnnotationEndpointRôle
DatabaseHealthCheck @Liveness GET /health/live Vérifie que le stockage en mémoire est accessible et que l'application est vivante.
WebAppReadinessCheck @Readiness GET /health/ready Vérifie que le contexte CDI est initialisé et que l'application est prête à traiter des requêtes.
ℹ
MicroProfile Health 4.0 — Les sondes sont automatiquement découvertes par Open Liberty et exposées sur http://localhost:9080/health. Aucune configuration XML supplémentaire n'est requise.
