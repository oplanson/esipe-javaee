Architecture Fonctionnelle

L'application est organisée en quatre domaines fonctionnels : production de messages, consommateurs MDB, persistance d'audit et interface de test HTTP. Le diagramme ci-dessous représente le flux complet des messages JMS.

Diagramme de flux JMS

Domaine 1 — Production de messages

ComposantTypeResponsabilité
TransactionEventProducer @ApplicationScoped Produit des TextMessage JSON vers transactionQueue avec priorité différenciée (TRANSFER=7, WITHDRAWAL=6, DEPOSIT=5). Publie les événements d'audit sur auditTopic. Envoie les notifications e-mail vers emailQueue avec la propriété notificationType='EMAIL'. Injecte un JMSContext via @JMSConnectionFactory("jms/connectionFactory").

Domaine 2 — Consommateurs MDB

ComposantDestinationResponsabilité
TransactionEventMDB transactionQueue Consomme les événements de transaction (DEPOSIT, WITHDRAWAL, TRANSFER). Valide la propriété messageFormat='JSON', désérialise le payload JSON, simule un traitement de 100 ms puis journalise le résultat. Concurrence : 10 instances.
EmailNotificationMDB emailQueue Consomme uniquement les messages dont le sélecteur notificationType='EMAIL' est vrai. Délègue l'envoi à EmailService. Concurrence : 5 instances.
AuditLoggingMDB auditTopic (durable) Abonné durable au topic d'audit (clientId=AuditClient, subscriptionName=AuditSubscription). Crée et persiste une entité AuditLog via JPA à chaque message reçu. Concurrence : 3 instances.
DeadLetterQueueMDB deadLetterQueue Capture les messages non traitables après épuisement des tentatives. Rejette explicitement les ObjectMessage (protection CVE-2015-7501). Persiste une entité FailedMessage en base de données. Concurrence : 2 instances.

Domaine 3 — Persistance d'audit

Entité JPATableResponsabilité
AuditLog audit_logs Enregistre chaque événement d'audit : type de transaction, identifiant de compte, statut, horodatage. Champ createdAt immutable, défini une seule fois par @PrePersist. Persisté par AuditLoggingMDB via EntityManager (EclipseLink).
FailedMessage failed_messages Capture les messages en erreur : payload original, type de message, cause de l'échec, nombre de tentatives, horodatage. Persisté par DeadLetterQueueMDB.

Domaine 4 — Interface de test HTTP

EndpointMéthodeAction déclenchée
/test-messaging/depositGETEnvoie un événement DEPOSIT sur transactionQueue (priorité 5)
/test-messaging/withdrawalGETEnvoie un événement WITHDRAWAL sur transactionQueue (priorité 6)
/test-messaging/transferGETEnvoie un événement TRANSFER sur transactionQueue (priorité 7)
/test-messaging/emailGETEnvoie une notification e-mail vers emailQueue avec notificationType='EMAIL'
/test-messaging/auditGETPublie un événement d'audit sur auditTopic
/test-messaging/allGETDéclenche les 5 types de messages en une seule requête
/test-messaging/batchGETEnvoie 10 messages en séquence pour tests de charge
