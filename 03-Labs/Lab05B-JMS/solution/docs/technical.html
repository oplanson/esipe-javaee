Architecture Technique

Architecture en couches Jakarta EE déployée sur Open Liberty. La couche HTTP déclenche le producteur JMS, qui distribue les messages vers des queues et un topic. Des MDBs consomment de manière asynchrone et persistent les données d'audit dans PostgreSQL via EclipseLink.

Diagramme en couches

Infrastructure JMS — Destinations

Ressource JNDITypeConfigurationConsommateur
jms/connectionFactory ConnectionFactory Pool : 5–20 connexions (maxPoolSize=20) Tous les MDBs + Producer
transactionQueue Queue P2P PERSISTENT · max 5000 messages · maxConcurrency=10 TransactionEventMDB
emailQueue Queue + Selector Message selector : notificationType='EMAIL' · maxConcurrency=5 EmailNotificationMDB
deadLetterQueue Dead Letter Queue maxConcurrency=2 DeadLetterQueueMDB
auditTopic Topic Pub/Sub Abonnement durable · clientId=AuditClient · subscriptionName=AuditSubscription · maxConcurrency=3 AuditLoggingMDB

Format de message & Sécurité

AspectValeur / Règle
Type de messageTextMessage — payload JSON sérialisé
Propriété obligatoiremessageFormat='JSON' — vérifiée par chaque MDB avant traitement
Sécurité désérialisationTous les MDBs valident messageFormat. DeadLetterQueueMDB rejette explicitement ObjectMessage (correction CVE-2015-7501)
Propriétés transactionstransactionType (DEPOSIT/WITHDRAWAL/TRANSFER), status, accountId
Propriétés e-mailnotificationType='EMAIL', customerEmail
Priorité messagesTRANSFER=7 (haute) > WITHDRAWAL=6 > DEPOSIT=5 > default=4
Mode de livraisonDeliveryMode.PERSISTENT — messages survivent au redémarrage du serveur
AcquittementAUTO_ACKNOWLEDGE — géré par le conteneur après traitement sans exception
