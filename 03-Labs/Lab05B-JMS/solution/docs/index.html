Banking JMS Application — Lab 05B

Application bancaire démontrant la messagerie asynchrone Jakarta Messaging 3.1 (JMS) sur Open Liberty. Elle met en œuvre les patterns Queue (point-à-point), Topic (publication/abonnement), Dead Letter Queue et la sécurisation de la désérialisation JSON.

Architecture Fonctionnelle

Architecture Technique

Couches Jakarta EE, infrastructure JMS (queues, topic, pool), format de message JSON, priorités et features Liberty.

Diagrammes de Séquences

3 flux : dépôt (queue P2P), audit topic (pub/sub durable) et gestion Dead Letter Queue.

Règles de Gestion

R1–R11 : sécurité de désérialisation, livraison persistante, priorités, message selector, acquittement et concurrence.
