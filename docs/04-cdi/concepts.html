Key Concepts

Comparisons, reference tables and glossary for CDI and transaction management.

CDI vs EJB

FeatureCDI BeanEJB (Session Bean)
Transaction managementVia @Transactional (CDI Interceptor)Natively integrated (CMT)
Declarative securityVia custom interceptor@RolesAllowed, @DenyAll built-in
Clustering & passivation❌ Not natively supported✅ Passivatable stateful beans
Remote access❌ No✅ Via @Remote
Complexity✅ Lightweight, POJO⚠️ Heavier, dedicated specification
Recommended useModern application services, microservicesLegacy applications, distributed transactions

CDI Scopes Compared

ScopeAnnotationLifetimeTypical use case
Application@ApplicationScopedApplication lifetimeStateless services, caches, configuration
Session@SessionScopedDuration of the HTTP user sessionCart, preferences, login state
Request@RequestScopedDuration of an HTTP requestForm processing, single operations
Conversation@ConversationScopedExplicitly managed conversationMulti-step wizards, long forms
Dependent@Dependent (default)Bound to the injecting beanValue objects, helpers, lightweight beans
Singleton (pseudo-scope)@Singleton (jakarta.enterprise.inject.Singleton)Application lifetime — no proxy, direct instanceShared resources where proxy overhead is undesirable; prefer @ApplicationScoped for general singletons

⚠️ Note on @Singleton: @Singleton in CDI is a pseudo-scope from jakarta.enterprise.inject.Singleton. Unlike @ApplicationScoped, it does not create a proxy — injection points receive the actual instance. This means it is not passivation-capable and subtypes cannot be proxied. For most singleton use cases, prefer @ApplicationScoped.

CMT vs BMT

AspectCMT — Container-Managed TransactionsBMT — Bean-Managed Transactions
ManagementDelegated to the container via @TransactionalManual via UserTransaction
Transaction codeAbsent from business code (declarative)Present in code (begin/commit/rollback)
Complexity✅ Low — annotations only⚠️ High — explicit error handling
FlexibilityLimited to standard propagation types✅ Full — custom transactional logic
Recommended forThe vast majority of use casesAdvanced cases: saga, long-running transactions
RollbackAutomatic on RuntimeExceptionExplicit: tx.rollback() in the catch block

Glossary

TermDefinition
CDIContexts and Dependency Injection — Jakarta EE specification for dependency injection and bean lifecycle management
@InjectStandard annotation (Jakarta Inject) asking the CDI container to inject a dependency into a field, constructor or method
@QualifierMeta-annotation for creating custom qualifiers to resolve ambiguity when injecting multiple implementations of the same type
@ProducesAnnotation declaring a method or field as a source of a CDI bean — useful for objects requiring complex creation logic
@InterceptorAnnotation marking a class as a CDI interceptor — intercepts method invocations to add cross-cutting behaviour
@DecoratorAnnotation marking a bean as a decorator — wraps an existing bean to enrich its behaviour, unlike interceptors which are type-agnostic
@ObservesAnnotation placed on a method parameter to subscribe to a CDI event type — the method is called synchronously in the same thread as the event producer
@ObservesAsyncAnnotation (CDI 2.0+ / Jakarta CDI 4.0) placed on a method parameter to subscribe to asynchronous CDI events — the method is called in a separate thread when event.fireAsync() is invoked
UserTransactionJakarta Transactions interface for programmatic (BMT) transaction management — begin(), commit(), rollback(), setRollbackOnly()
