01Goal of the labObjectif du lab

You build a client management web application for the banking case study that runs through the whole course, this time with Jakarta Faces instead of hand-written servlets and JSP. Data stays in memory (a CDI application-scoped service); the database arrives in Lab 03. The goal is to understand how a Faces page, an Expression Language binding and a CDI bean work together. Vous construisez une application web de gestion de clients pour le cas d'étude bancaire qui sert de fil rouge au cours, cette fois avec Jakarta Faces plutôt que des servlets et des JSP écrites à la main. Les données restent en mémoire (un service CDI de portée application) ; la base de données arrive au Lab 03. L'objectif est de comprendre comment une page Faces, une liaison par Expression Language et un bean CDI fonctionnent ensemble.

The redeploy loopLa boucle de redéploiement

The WAR is baked into the container image, so after every change you rebuild and restart. You will use these commands many times: Le WAR est embarqué dans l'image du conteneur : après chaque modification, vous reconstruisez et relancez. Vous utiliserez ces commandes de nombreuses fois : 

mvn clean package -DskipTests
podman rm -f lab02b-jsf 2>/dev/null
podman build -t lab02b-jsf:latest -f Containerfile .
podman run -d --name lab02b-jsf -p 127.0.0.1:9080:9080 lab02b-jsf:latest
until curl -fs http://localhost:9080/health/ready >/dev/null; do sleep 2; done; echo "ready"

The container is bound to 127.0.0.1 so the application is reachable from your machine only. The first mvn package downloads Open Liberty and may take several minutes. The loop works from step 2 on, once the Containerfile exists. The readiness check is on /health/ready (at the server root, not under /lab02b-jsf); it answers UP as soon as the server is started.
