01Goal of the labObjectif du lab

In Lab 02, data lived only in memory in a HashMap and disappeared each time the server restarted. In this lab, you transition the banking application to enterprise-grade persistence: entities mapped to PostgreSQL tables via JPA, bidirectional relationships, transactional CRUD operations via EntityManager, database migrations versioned with Flyway, and environment configuration resolved through JNDI. Dans le Lab 02, les données vivaient uniquement en mémoire dans une HashMap et disparaissaient à chaque redémarrage du serveur. Dans ce lab, vous faites évoluer l'application bancaire vers une persistance d'entreprise : entités mappées sur des tables PostgreSQL via JPA, relations bidirectionnelles, opérations CRUD transactionnelles via EntityManager, migrations de schéma versionnées avec Flyway et configuration d'environnement résolue par JNDI.

Discrepancies between original README and real code

The original README mentions Hibernate and CDI annotations (such as @Inject and @Transactional). In this course architecture, CDI is formally introduced in Lab 04. Lab 03 focuses on standard JPA with Open Liberty's native EclipseLink provider (RESOURCE_LOCAL, Singleton ClientService.getInstance(), programmatic EntityTransaction), Flyway migrations via a @WebListener ServletContextListener, and JNDI lookups with InitialContext. Furthermore, the migration files (V1, V2, V3), persistence.xml, DatabaseMigrationStartup.java, TransactionValidatorServlet.java, and Containerfile are absent from starter/ and must be created. This guide follows the real code of starter/ and solution/.

Database security in development

The container environment uses demonstration credentials (bankuser / bankpassword). In production, credentials must never be hard-coded and must be provided via secret management. Ports are bound to 127.0.0.1 to prevent remote exposure.

Sécurité de la base en développement

L'environnement en conteneur utilise des identifiants de démonstration (bankuser / bankpassword). En production, aucun identifiant ne doit être codé en dur et la configuration doit passer par un gestionnaire de secrets. Les ports sont liés à 127.0.0.1 pour éviter toute exposition distante.

Hint 2 — DatabaseMigrationStartup skeletonIndice 2 — squelette DatabaseMigrationStartup 
@WebListener
public class DatabaseMigrationStartup implements ServletContextListener {
    @Override
    public void contextInitialized(ServletContextEvent sce) {
        try {
            InitialContext ctx = new InitialContext();
            DataSource ds = (DataSource) ctx.lookup("jdbc/bankingDS");
            Flyway flyway = Flyway.configure()
                    .dataSource(ds)
                    .locations("classpath:db/migration")
                    .baselineOnMigrate(true)
                    .load();
            flyway.migrate();
        } catch (Exception e) {
            e.printStackTrace();
        }
    }
}

Hint 2 — create method exampleIndice 2 — exemple de méthode create 
public Client create(Client client) {
    EntityManager em = createEntityManager();
    EntityTransaction tx = em.getTransaction();
    try {
        tx.begin();
        em.persist(client);
        em.flush();
        tx.commit();
        return client;
    } catch (Exception e) {
        if (tx.isActive()) tx.rollback();
        throw new RuntimeException("Failed to create client", e);
    } finally {
        em.close();
    }
}

Connection to localhost:5432 refused PostgreSQL container is not running. Start it with podman compose up -d and check status with podman ps.Le conteneur PostgreSQL n'est pas démarré. Lancez-le avec podman compose up -d et vérifiez avec podman ps.
FlywayException: Table "clients" already exists The database schema has conflicting migrations. Reset the database: podman compose down -v && podman compose up -d.Le schéma de base contient des migrations en conflit. Réinitialisez la base : podman compose down -v && podman compose up -d.
NameNotFoundException: jdbc/bankingDS DataSource declaration is missing in server.xml or <resource-ref> is missing in web.xml.La déclaration de DataSource manque dans server.xml ou le <resource-ref> manque dans web.xml.
PersistenceException: No Persistence provider for EntityManager named bankingPU persistence.xml is missing in src/main/resources/META-INF/ or provider class name is mistyped.persistence.xml est absent dans src/main/resources/META-INF/ ou le nom du provider contient une faute de frappe.
LazyInitializationException / empty accounts Accounts collection was accessed after EntityManager was closed. Use findByIdWithAccounts with LEFT JOIN FETCH.La collection de comptes a été accédée après fermeture de l'EntityManager. Utilisez findByIdWithAccounts avec LEFT JOIN FETCH.
Port 5432 or 9080 already in use Another process holds the port. Check with lsof -i :5432 or lsof -i :9080 and stop conflicting containers.Un autre processus occupe le port. Vérifiez avec lsof -i :5432 ou lsof -i :9080 et arrêtez les conteneurs en conflit.
