01Goal of the labObjectif du lab

The application of Lab 03 used a hand-made Singleton service and manual transactions. Here the business logic lives in EJBs: the container pools them, wraps every business method in a transaction, secures them with roles, schedules timers and delivers JMS messages to a message-driven bean. You also repair a starter that does not compile and a solution with three configuration traps.L'application du Lab 03 utilisait un service Singleton écrit à la main et des transactions manuelles. Ici, la logique métier vit dans des EJB : le conteneur les met en pool, entoure chaque méthode métier d'une transaction, les protège par des rôles, planifie des timers et livre des messages JMS à un message-driven bean. Vous réparez aussi un starter qui ne compile pas et une solution qui contient trois pièges de configuration.

Discrepancies between README, starter and solution

This guide follows diff -r starter solution and the real files, not the README.

  • The README describes a Report entity, an EntityManagerProducer, a WebAppReadinessCheck, REST endpoints under /lab04b/api/..., @Asynchronous methods and SessionContext checks: none of them exists in the starter or the solution.
  • The README says port 9080; the starter uses 9081 in bootstrap.properties and server.xml, and 9080 in the compose file and the solution.
  • Package-private enums in Account.java / Transaction.java and three missing EJBs (ClientServiceBean, TransactionBatchBean, ReportGeneratorBean) make the starter fail to compile; Client, three enums, three migrations and banking.jsp are missing (steps 2, 3, 6, 8, 10, 12).
  • The starter Containerfile and server.xml refer to lab04b-ejb.war while Maven builds banking-ejb-app.war.
  • Solution traps fixed here: JMS queue name jms/NotificationQueue vs jms/notificationQueue in the MDB, missing jmsActivationSpec, persistent timers (CNTR4019E).
  • The solution resets the database at every start (flyway.clean()) and its index.html advertises demo accounts that are not enforced (no appSecurity feature). Use them as a demonstration only.

@Singleton
@Startup
@TransactionManagement(TransactionManagementType.BEAN)
public class DatabaseMigrationStartup {
    @Resource(lookup = "jdbc/bankingDS")
    private DataSource dataSource;

    @PostConstruct
    public void init() {
        Flyway flyway = Flyway.configure()
                .dataSource(dataSource)
                .locations("classpath:db/migration")
                .cleanDisabled(false)      // lab only
                .baselineVersion("0").baselineOnMigrate(true)
                .load();
        flyway.clean();
        flyway.migrate();
    }
}
