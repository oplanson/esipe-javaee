Lab 08

Microservices ArchitectureArchitecture microservices

You split the banking application into three services: client-service, account-service and an api-gateway (BFF). Each service owns its PostgreSQL database, the services talk through MicroProfile Rest Client protected by fault tolerance (Retry, CircuitBreaker, Timeout, Fallback), and the gateway routes and aggregates the calls. Vous découpez l'application bancaire en trois services : client-service, account-service et une api-gateway (BFF). Chaque service possède sa propre base PostgreSQL, les services dialoguent via MicroProfile Rest Client protégé par la tolérance aux pannes (Retry, CircuitBreaker, Timeout, Fallback), et la gateway route et agrège les appels.

Starter anomalies — read before you start
  • The TODO hints suggest database.url / database.password keys and URLs such as http://client-service:9081. The solution actually reads the database settings from DB_* environment variables (server.xml + bootstrap.properties) and uses port 9080 inside every container plus the /api suffix. Follow this guide, not the hints.
  • The starter server.xml files declare http.port 9081 / 9082 as a default, while the compose file maps host ports to container port 9080. The solution moves the port to bootstrap.properties (9080).
  • The starter docker-compose.yml uses build.context: ./solution/..., a path that does not exist from starter/; it also declares the obsolete version key and publishes ports on all interfaces. The solution compose file only starts the two databases.
  • The Containerfile of the starter has no PostgreSQL driver, no EXPOSE and no CMD.
  • The README.md of the starter announces JSP views and "Docker Compose configuration" as provided; only the compose file and css/style.css are present. run-lab.sh runs docker-compose from the lab root (no compose file there) and mentions a stop-lab.sh that does not exist.
  • The solution file api-gateway/URL-STRUCTURE.md documents the context root /web, but the solution server.xml uses /; the gateway REST API is served at /api/... and the servlets at /web/.... The links /web/api/... of the solution index.html therefore do not match the code.
  • The README announces a duration of 4 hours; the sum of the steps below is 6 hours (the guide retains the sum).
  • The mp.fault.tolerance.* keys of the solution microprofile-config.properties do not follow the MicroProfile Fault Tolerance override syntax (Retry/maxRetries, MyClass/method/Timeout/value); the values really applied are the ones written in the annotations.
  • The db.* keys of the solution microprofile-config.properties are not read by any Java class.
