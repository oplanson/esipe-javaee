🔒 Security Fundamentals

🔑 Authentication vs Authorization

Distinct definitions

ConceptFundamental questionMechanismResult
AuthenticationWho are you?Credentials, tokens, biometricsProven identity (Principal)
AuthorizationWhat can you do?Roles, permissions, policiesAccess granted or denied

Typical authentication flow

  1. Client — submits credentials (login + password)
  2. Server — verifies credentials against the IdentityStore
  3. Server — generates a signed token (JWT) with claims and expiration
  4. Client — receives the token and stores it (memory, HTTP-only cookie)
  5. Client — sends the token in each subsequent request (Authorization: Bearer <token>)
  6. Server — validates the token signature and checks roles

Multi-Factor Authentication (MFA)

  • Factor 1 (knowledge): password, PIN, security question
  • Factor 2 (possession): TOTP (Google Authenticator), SMS OTP, FIDO2 key
  • Factor 3 (inherence): fingerprint, facial recognition
🔐 Authentication Methods

Basic Auth

  • Credentials Base64-encoded in the HTTP header: Authorization: Basic dXNlcjpwYXNz
  • Simple to implement, but credentials transit on every request
  • ⚠️ Insecure without HTTPS — Base64 is not encryption
  • Usage: internal APIs, development tools

Form-Based Authentication

  • Dedicated HTML form (login page) submitted via POST
  • Session created server-side after success (stateful)
  • Mandatory CSRF protection
  • Jakarta EE : @FormAuthenticationMechanismDefinition

Token-Based Authentication (JWT)

  • Cryptographically signed self-contained token
  • Stateless — no server session required
  • Transmitted in Authorization: Bearer <token>
  • Ideal for REST APIs and microservices architectures

Tip: MicroProfile JWT Propagation (MP-JWT) standardizes JWT-based authentication across microservices. Annotate your JAX-RS application with @LoginConfig(authMethod="MP-JWT") and inject claims with @Claim.

Certificate-Based Authentication (mTLS)

  • X.509 certificate on both client and server
  • Mutual TLS — bidirectional authentication
  • Usage: service-to-service in microservices, critical communications

🛡️ Authorization Models

RBAC — Role-Based Access Control

Permissions are assigned to roles, users obtain roles.

  • ADMIN — full access (read, write, delete, administration)
  • USER — read and write access on own resources
  • VIEWER — read-only access

ABAC — Attribute-Based Access Control

Access decisions are based on attributes from multiple dimensions:

  • User attributes: department, clearance level, location
  • Resource attributes: data classification, owner, sensitivity
  • Environment attributes: time, IP address, context state

Declarative vs programmatic security

⚙️ Jakarta Security API

Jakarta Security Architecture

  • @HttpAuthenticationMechanism — intercepts HTTP requests, extracts and validates credentials
  • @IdentityStore — verifies credentials and returns the user's groups/roles
  • SecurityContext — programmatic API to query the current identity
  • HttpMessageContext — provides access to the HTTP context in mechanisms

Built-in mechanisms

AnnotationTypeUsage
@BasicAuthenticationMechanismDefinitionBasic AuthSimple APIs, internal tools
@FormAuthenticationMechanismDefinitionForm-BasedWeb applications with HTML login
@CustomFormAuthenticationMechanismDefinitionCustom FormAJAX login, modern forms

Jakarta Security flow

  1. HTTP request received by the Jakarta EE container
  2. HttpAuthenticationMechanism.validateRequest() is invoked
  3. Extracted credentials are passed to IdentityStore.validate()
  4. On success, a CallerPrincipalCallback is created
  5. The SecurityContext is populated with identity and groups
  6. The @RolesAllowed annotations are evaluated
🎫 JWT and MicroProfile JWT

JWT Token Structure

A JWT is composed of three Base64URL-encoded parts separated by dots: header.payload.signature

PartContentExample
HeaderSignature algorithm and type{"alg":"RS256","typ":"JWT"}
PayloadClaims: identity, roles, expiration{"sub":"alice","groups":["USER"],"exp":1234567890}
SignatureHMAC/RSA of header + payloadRSASHA256(base64Header + "." + base64Payload, key)

Standard claims (RFC 7519)

  • iss (issuer) — token issuer
  • sub (subject) — user identifier
  • aud (audience) — expected recipient(s)
  • exp (expiration time) — expiration Unix timestamp
  • iat (issued at) — issuance Unix timestamp
  • groups (MicroProfile) — list of user roles/groups

MicroProfile JWT Configuration

  • @LoginConfig(authMethod="MP-JWT") on the Application class
  • @RolesAllowed({"USER","ADMIN"}) on JAX-RS methods
  • @Inject @Claim("sub") String subject — claims injection into CDI beans
  • Properties: mp.jwt.verify.publickey.location and mp.jwt.verify.issuer
🔏 HTTPS/TLS — Configuration

Asymmetric encryption

  • Public key — freely shared, encrypts data and verifies signatures
  • Private key — secret, decrypts and signs
  • TLS Handshake: certificate exchange → algorithm negotiation → encrypted session

Certificate types

TypeIssuerCostBrowser trustUsage
Self-signedYourselfFree❌ NoDevelopment, testing
CA-signed (DV)Let's Encrypt, DigiCertFree / Paid✅ YesPublic websites
CA-signed (EV)DigiCert, SectigoPaid✅ YesE-commerce, banking

Liberty configuration and best practices

  • keyStore — contains the server private key and certificate
  • trustStore — contains trusted CA certificates
  • HSTS header — Strict-Transport-Security: max-age=31536000; includeSubDomains forces HTTPS
  • Perfect Forward Secrecy — use ECDHE/DHE so that compromising the private key does not affect past sessions
  • TLS 1.2+ mandatory — disable SSLv3, TLS 1.0, TLS 1.1
🌐 REST API Security

CORS — Cross-Origin Resource Sharing

  • Browser mechanism that controls cross-origin requests
  • Preflight request — OPTIONS request sent before cross-origin POST/PUT/DELETE
  • Response headers: Access-Control-Allow-Origin, Access-Control-Allow-Methods, Access-Control-Allow-Headers
  • Never use Access-Control-Allow-Origin: * with credentials

CSRF Protection

  • Attack exploiting the server's trust in the victim's browser
  • CSRF Token — random session value, transmitted in the X-CSRF-Token header
  • Validate with constant-time comparison (MessageDigest.isEqual()) to prevent timing attacks
  • SameSite=Strict cookie as additional defense

Input validation

  • Validate all inputs server-side (Jakarta Validation / Bean Validation)
  • Sanitize data to prevent XSS (encode HTML characters)
  • Use prepared queries (JPA criteria, parameterized JPQL) against SQL injection

Rate Limiting and API Keys

  • Rate limiting — limit the number of requests per IP/token per time window
  • API Keys — identification of application clients (not users)
  • OAuth2 — standardized authorization delegation (prefer for third-party access)
☁️ Microservices Security

Service-to-service authentication

  • mTLS (Mutual TLS) — each service has a certificate, bidirectional authentication
  • JWT Propagation — the user JWT is passed service-to-service in the Authorization header
  • Service Accounts — dedicated credentials per service (avoid shared credentials)

Secrets management

  • Environment variables — basic method, injected by the orchestrator (Kubernetes Secrets)
  • HashiCorp Vault — secure storage, automatic secret rotation
  • Never commit secrets in source code or container images
  • MicroProfile Config allows injecting secrets via @ConfigProperty from the environment
