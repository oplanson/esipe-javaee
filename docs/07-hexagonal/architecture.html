Hexagonal Architecture — Diagram

Visual representation of the Ports & Adapters pattern — domain at the centre, adapters at the periphery.

Primary Adapters (Driving)

Primary adapters initiate the execution of a use case. They translate an external event (HTTP request, message, CLI command) into a call on a primary port of the domain. The adapter contains no business logic — it delegates immediately to the port.

  • REST Controllers / Resources — JAX-RS resources annotated @Path, receive HTTP requests and call the use case
  • Servlets — @WebServlet for non-REST use cases (forms, downloads)
  • Message Consumers (initiating requests) — Message-Driven Beans that process an incoming message and trigger a use case
  • CLI Commands — command-line tools for maintenance or batch operations
  • Test Drivers — JUnit test classes that call use cases directly — this is the main value of the architecture!

Secondary Adapters (Driven)

Secondary adapters receive calls from the domain via secondary ports. They translate the domain's requests (in business terms) into technical calls (SQL, JMS, HTTP). The adapter performs the mapping between domain objects and technical entities.

  • JPA Repositories — implement secondary ports with JPA (EntityManager, JPA entities separate from domain entities)
  • JMS Producers / Consumers (driven) — publish business events to a message broker
  • External HTTP Clients (Rest Client) — MicroProfile Rest Client calling third-party APIs (payment system, fraud service)
  • File System Adapters — file reading/writing (CSV import, report export)
  • In-Memory Adapters (for tests) — HashMap-based implementations for unit testing use cases without a database

Dependency Flow

The fundamental rule of hexagonal architecture is that all dependency arrows point towards the domain, never outward:

  • Primary adapters depend on primary port interfaces (defined in the domain)
  • Secondary adapters implement secondary port interfaces (defined in the domain)
  • The domain has zero knowledge of adapters — it does not import or reference them
  • If the domain wants to talk to the outside, it defines an interface (secondary port) — the outside implements it
  • Result: replacing an adapter (e.g. migrating from JPA to MongoDB) requires no modification in the domain or use cases
