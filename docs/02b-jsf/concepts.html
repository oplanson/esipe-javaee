CDI Bean Scopes in JSF

AnnotationLifetimeTypical use
@RequestScopedDuration of an HTTP requestOne-off actions, simple forms
@ViewScoped
(jakarta.faces.view.ViewScoped)		 Duration of a JSF view Forms with AJAX, in-place editing
@SessionScopedDuration of an HTTP sessionLogged-in user, cart, preferences
@ApplicationScopedDuration of the applicationGlobal caches, reference data
@DependentDepends on the parent beanUtility beans with no own state

⚠️ Important: use jakarta.faces.view.ViewScoped (CDI-compatible, Jakarta EE 9+), NOT the legacy javax.faces.bean.ViewScoped which was tied to the deprecated @ManagedBean model.

@ManagedBean (legacy) vs @Named (CDI)

Feature@ManagedBean (legacy)@Named + CDI (recommended)
Package javax.faces.bean / jakarta.faces.bean jakarta.inject.Named + CDI scopes
Status ❌ Deprecated since JSF 2.3 — removed in Jakarta EE 10 ✅ Standard — recommended approach for all new projects
CDI injection (@Inject) ⚠️ Partial support only ✅ Full CDI integration
Interceptors / Decorators ❌ Not supported ✅ Fully supported
@ViewScoped annotation javax.faces.bean.ViewScoped (legacy) jakarta.faces.view.ViewScoped (CDI)

JSF Lifecycle Phases

#PhaseDescriptionWhat happens
1Restore ViewRestore or create the viewRebuild the UIComponent tree from ViewState or create a new tree
2Apply Request ValuesApply request valuesEach component reads its value from the HTTP parameters and stores it locally
3Process ValidationsRun validationsValidators and converters run; errors are added to the FacesContext
4Update Model ValuesUpdate the modelValidated values are pushed to bean properties via ValueExpressions
5Invoke ApplicationInvoke the applicationAction methods and action listeners run; the outcome determines navigation
6Render ResponseRender the responseThe component tree is encoded to HTML and sent to the client; ViewState is saved

Glossary

TermDefinition
JSFJavaServer Faces — component-oriented MVC framework for building Jakarta EE web interfaces; specification renamed Jakarta Faces since EE 9
FaceletsOfficial JSF templating engine since JSF 2.0, replacing JSP; files have the .xhtml extension and follow XML syntax
Managed BeanCDI bean annotated @Named acting as a controller in JSF; exposes its properties and methods to the Expression Language of Facelets views
ELExpression Language — #{...} syntax allowing access to beans and their properties from JSF views; supports property navigation and method calls
faces-config.xmlJSF XML configuration file in /WEB-INF/ for declaring explicit navigation rules, converters, validators and managed beans (deprecated for the latter)
UIComponentBase class of all JSF components forming the component tree — each JSF tag such as h:inputText creates a UIComponent instance
ValueExpressionEL expression #{bean.property} enabling bidirectional binding (read and write) of a value between a JSF component and a CDI bean
ActionEventEvent triggered by an action component (h:commandButton, h:commandLink); handled by ActionListeners or action methods returning a navigation outcome
