Concepts clés

Comparatifs, tableaux de référence et glossaire pour JMS et la messagerie enterprise.

Messagerie vs Appels Directs

AspectAppels Directs (REST/EJB)Messagerie JMS
CouplageFort — l'émetteur connaît le récepteurFaible — via broker de messages
DisponibilitéLes deux services doivent être actifsDécouplage temporel — tolérance aux pannes
OrdreSéquentiel garanti dans un appelFIFO par Queue, non garanti sur Topic
ScalabilitéLimitée par le service le plus lentNaturelle — plusieurs consommateurs sur une Queue
ComplexitéSimple à implémenterInfrastructure broker requise
Use CaseRequête/réponse synchrone, CRUD APITraitement asynchrone, intégration, événements

Queue vs Topic

FeatureQueue (Point-à-Point)Topic (Pub/Sub)
ModèlePoint-à-PointPublish/Subscribe
ConsommateursUn seul consommateur par messageTous les abonnés reçoivent le message
PersistanceMessages conservés jusqu'à consommationDépend du type d'abonnement
Abonnement durableNon applicableOui — subscriptionDurability="Durable"
Load balancing✅ Naturel entre consommateurs❌ Chaque abonné traite tous les messages
RejoueNon (message supprimé après ACK)Possible avec durable subscription
Use CaseFile de tâches, commandes, workflowNotifications, broadcast, événements métier

TypeDescriptionUse Case

StreamMessageFlux de primitifs Java séquentielsProtocoles séquentiels, données numériques

Transactions JMS dans un MDB

AspectCMT — Container-Managed TransactionsBMT — Bean-Managed Transactions
GestionDéléguée au conteneur — automatiqueManuelle via UserTransaction
Annotation@TransactionAttribute(REQUIRED) (défaut MDB)@TransactionManagement(BEAN)
ACK JMSInclus dans la transaction conteneurSéparé — géré par ut.begin()/commit()
RollbackAutomatique sur exception — message rélivréExplicite — ut.rollback() dans le catch
Poison messageGéré par le broker après N tentatives → DLQÀ gérer manuellement dans le code
Recommandé✅ Oui — grande majorité des casCas avancés uniquement

Glossaire

TermeDéfinition
JMSJakarta Messaging Service — spécification Jakarta EE définissant une API standard pour la communication asynchrone par messages entre applications
QueueDestination JMS du modèle Point-à-Point — chaque message est consommé par un seul consommateur ; les messages sont persistés jusqu'à consommation
TopicDestination JMS du modèle Publish/Subscribe — chaque message publié est distribué à tous les abonnés actifs (ou durables)
MDBMessage-Driven Bean — EJB déclenché automatiquement par l'arrivée d'un message JMS ; implémente MessageListener
@MessageDrivenAnnotation Jakarta EE déclarant un EJB comme MDB et configurant son abonnement JMS via activationConfig
Dead Letter QueueFile de messages non-traitables — reçoit les messages qui ont échoué N fois consécutives ; permet l'analyse et la reprise sans perte
JMSContextInterface JMS 2.0 combinant Connection et Session en un seul objet injectable — simplifie drastiquement le code producteur/consommateur
MessageSelectorFiltre SQL-like appliqué sur les propriétés des messages pour ne consommer que les messages correspondant à des critères précis
