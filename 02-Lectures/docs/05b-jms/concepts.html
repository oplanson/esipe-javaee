Key Concepts

Comparisons, reference tables and glossary for JMS and enterprise messaging.

Messaging vs Direct Calls

Note: JMS 3.0 is included in Jakarta EE 10+

AspectDirect Calls (REST/EJB)JMS Messaging
CouplingTight — the sender knows the receiverLoose — via message broker
AvailabilityBoth services must be activeTemporal decoupling — fault tolerance
OrderSequential guaranteed within a callFIFO per Queue, not guaranteed on Topic
ScalabilityLimited by the slowest serviceNatural — multiple consumers on a Queue
ComplexitySimple to implementBroker infrastructure required
Use CaseSynchronous request/response, CRUD APIAsynchronous processing, integration, events

Queue vs Topic

FeatureQueue (Point-to-Point)Topic (Pub/Sub)
ModelPoint-to-PointPublish/Subscribe
ConsumersOne consumer per messageAll subscribers receive the message
PersistenceMessages retained until consumedDepends on subscription type
Durable subscriptionNot applicableOui — subscriptionDurability="Durable"
Load balancing✅ Natural between consumers❌ Each subscriber processes all messages
ReplayNo (message deleted after ACK)Possible with durable subscription
Use CaseTask queue, orders, workflowNotifications, broadcast, business events

Glossary

TermDefinition
JMSJakarta Messaging Service — Jakarta EE specification defining a standard API for asynchronous message-based communication between applications
QueueJMS destination for the Point-to-Point model — each message is consumed by a single consumer; messages are persisted until consumed
TopicJMS destination for the Publish/Subscribe model — each published message is distributed to all active (or durable) subscribers
MDBMessage-Driven Bean — EJB automatically triggered by the arrival of a JMS message; implements MessageListener
@MessageDrivenJakarta EE annotation declaring an EJB as an MDB and configuring its JMS subscription via activationConfig
Dead Letter QueueQueue for unprocessable messages — receives messages that have failed N consecutive times; enables analysis and recovery without data loss
JMSContextJMS 2.0 interface combining Connection and Session into a single injectable object — drastically simplifies producer/consumer code
MessageSelectorSQL-like filter applied on message properties to consume only messages matching specific criteria
