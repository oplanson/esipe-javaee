Concepts clés

Comparatifs, tableaux de référence et glossaire pour JAX-RS, REST et MicroProfile.

REST vs SOAP

AspectRESTSOAP
ParadigmeStyle architectural basé sur les ressourcesProtocole de messagerie basé sur les opérations
FormatJSON (majoritaire), XML, texte libreXML obligatoire (enveloppe SOAP)
ProtocoleHTTP — exploite pleinement les verbes et statutsHTTP, SMTP, TCP — HTTP uniquement comme tunnel
Verbosité✅ Faible — payloads compacts⚠️ Élevée — enveloppe XML volumineuse
Courbe d'apprentissage✅ Faible — conventions intuitives⚠️ Élevée — WSDL, WS-Security, WS-*, schémas XSD
Performance✅ Meilleure — format léger, cache HTTP natif⚠️ Plus faible — sérialisation XML coûteuse
Cas d'usageAPIs web, microservices, applications mobilesServices d'entreprise legacy, transactions distribuées, contrats formels

Codes de Statut HTTP pour APIs REST

CodeSignificationQuand l'utiliser
200 OKSuccès avec corps de réponseGET, PUT, PATCH réussis avec données retournées
201 CreatedRessource créée avec succèsPOST réussi — toujours inclure l'en-tête Location
204 No ContentSuccès sans corps de réponseDELETE réussi, PUT sans retour de données
400 Bad RequestRequête invalide ou malforméeValidation Bean Validation échouée, JSON invalide, paramètres manquants
401 UnauthorizedAuthentification requiseToken absent, expiré ou invalide — accompagné de l'en-tête WWW-Authenticate
403 ForbiddenAutorisations insuffisantesUtilisateur authentifié mais sans les droits sur la ressource
404 Not FoundRessource introuvableID inexistant, chemin inconnu
409 ConflictConflit d'étatDoublon, optimistic lock conflict, état métier incompatible
500 Internal Server ErrorErreur serveur non géréeException inattendue — retourner un message générique, pas de stack trace

Glossaire

TermeDéfinition
JAX-RSJakarta RESTful Web Services — spécification Jakarta EE pour la création de services REST via des annotations sur des classes POJO
JSON-BJakarta JSON Binding — spécification de sérialisation/désérialisation bidirectionnelle entre objets Java et JSON, intégrée nativement dans Jakarta EE
HATEOASHypermedia As The Engine Of Application State — contrainte REST de niveau 3 stipulant que les réponses contiennent des hyperliens vers les transitions d'état possibles
ExceptionMapperInterface JAX-RS permettant de transformer une exception Java en réponse HTTP structurée — découple la logique métier du protocole HTTP
@ProviderAnnotation JAX-RS marquant une classe comme composant d'infrastructure (ExceptionMapper, MessageBodyWriter, ContainerRequestFilter…) — enregistrement automatique par le runtime
@RegisterRestClientAnnotation MicroProfile Rest Client transformant une interface Java annotée JAX-RS en client HTTP type-safe injectable via CDI
OpenAPISpécification standard (anciennement Swagger) pour décrire des APIs REST — MicroProfile OpenAPI génère automatiquement le document depuis les annotations Java
Richardson Maturity ModelModèle en 4 niveaux (0 à 3) proposé par Leonard Richardson pour mesurer la maturité d'une API REST — niveau 2 (verbes HTTP + codes statut) est le standard pratique
