Key Concepts

Comparisons, reference tables and glossary for Jakarta REST (JAX-RS), REST and MicroProfile.

REST vs SOAP

AspectRESTSOAP
ParadigmResource-based architectural styleOperation-based messaging protocol
FormatJSON (dominant), XML, plain textXML mandatory (SOAP envelope)
ProtocolHTTP — fully leverages verbs and status codesHTTP, SMTP, TCP — HTTP used as tunnel only
Verbosity✅ Low — compact payloads⚠️ High — large XML envelope
Learning curve✅ Low — intuitive conventions⚠️ High — WSDL, WS-Security, WS-*, XSD schemas
Performance✅ Better — lightweight format, native HTTP cache⚠️ Lower — costly XML serialization
Use CaseWeb APIs, microservices, mobile applicationsLegacy enterprise services, distributed transactions, formal contracts

Glossary

TermDefinition
Jakarta RESTJakarta RESTful Web Services (formerly JAX-RS) — Jakarta EE specification for creating REST services via annotations on POJO classes. All annotations are in the jakarta.ws.rs.* package.
JSON-BJakarta JSON Binding — specification for bidirectional serialization/deserialization between Java objects and JSON, natively integrated in Jakarta EE.
HATEOASHypermedia As The Engine Of Application State — level 3 REST constraint stipulating that responses contain hyperlinks to possible state transitions.
ExceptionMapperJakarta REST interface for transforming a Java exception into a structured HTTP response — decouples business logic from HTTP protocol.
@ProviderJakarta REST annotation marking a class as an infrastructure component (ExceptionMapper, MessageBodyWriter, ContainerRequestFilter…) — automatic registration by the runtime.
@RegisterRestClientMicroProfile Rest Client annotation transforming a Jakarta REST-annotated Java interface into a type-safe HTTP client injectable via CDI.
OpenAPIStandard specification (formerly Swagger) for describing REST APIs — MicroProfile OpenAPI automatically generates the document from Java annotations.
Richardson Maturity Model4-level model (0 to 3) proposed by Leonard Richardson to measure the maturity of a REST API — level 2 (HTTP verbs + status codes) is the practical standard.
