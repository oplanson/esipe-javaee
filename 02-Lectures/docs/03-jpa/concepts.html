Concepts clés

Comparatifs, tableaux de référence et glossaire pour JPA & intégration base de données.

JPA vs JDBC

CritèreJDBCJPA
Niveau d'abstractionBas — SQL direct, ResultSet manuelHaut — objets Java, mapping automatique
Portabilité❌ SQL souvent spécifique au SGBD✅ Indépendant du SGBD (dialectes)
Quantité de code❌ Verbeux — try/catch, close(), mapping✅ Concis — annotations, génération auto
Performances✅ Contrôle total sur le SQL⚠️ Overhead ORM, mais cache intégré
Courbe d'apprentissage✅ Simple à apprendre⚠️ Concepts avancés (lazy, cascade, contexte)

Stratégies de Génération d'ID

StratégieDescriptionUtilisation recommandée
AUTOLe provider JPA choisit la stratégie selon le SGBDPrototypage rapide, portabilité maximale
IDENTITYColonne auto-increment gérée par la BDPostgreSQL (SERIAL), MySQL (AUTO_INCREMENT)
SEQUENCESéquence base de données dédiéePostgreSQL, Oracle — meilleures performances en lot
TABLETable dédiée simulant une séquencePortabilité totale entre tous les SGBD

Types de Fetch JPA

TypeComportementDéfaut pourQuand l'utiliser
LAZYChargement différé — données chargées à l'accès@OneToMany, @ManyToManyCollections volumineuses, rarement accédées
EAGERChargement immédiat — données jointes à la requête@ManyToOne, @OneToOneAssociations toujours nécessaires

Types de Cascade JPA

TypeDescription
PERSISTLa persistance de l'entité parent propage la persistance aux entités liées
MERGELe merge de l'entité parent propage le merge aux entités liées
REMOVELa suppression de l'entité parent supprime aussi les entités liées
REFRESHLe refresh du parent recharge aussi les entités liées depuis la BD
DETACHLe détachement du parent détache aussi les entités liées
ALLApplique tous les types de cascade (équivalent de tous les précédents)

Transactions CMT vs BMT

CritèreCMT — Container-ManagedBMT — Bean-Managed
Qui contrôleLe conteneur Jakarta EELe développeur
Annotation@Transactional (CDI) ou @TransactionAttribute (EJB)@Inject UserTransaction ut
DémarrageAutomatique à l'entrée de la méthode annotéeExplicite : ut.begin()
Commit / RollbackAutomatique — rollback sur exception non-vérifiéeExplicite : ut.commit() / ut.rollback()
Cas d'utilisationCas standard (recommandé)Logique transactionnelle complexe, multi-transactions

États d'une Entité JPA

ÉtatDescriptionTransition vers Managed
New / TransientObjet Java ordinaire, inconnu de l'EntityManager et de la BDem.persist(entity)
ManagedSous contrôle du contexte de persistance — modifications automatiquement synchronisées— (déjà managed)
DetachedEntité qui existait en BD mais dont le contexte est fermé ou explicitement détachéem.merge(entity)
RemovedMarquée pour suppression — sera effacée au prochain flush/commitem.persist(entity) (annule la suppression)

Glossaire

TermeDéfinition
EntityManagerInterface principale de JPA — gère le cycle de vie des entités (persist, merge, remove, find, query)
PersistenceContextCache de premier niveau associé à l'EntityManager — ensemble des entités managed dans une transaction
JPQLJakarta Persistence Query Language — langage de requête orienté objet opérant sur les entités Java, pas sur les tables SQL
Criteria APIAPI Java type-safe pour construire des requêtes JPA dynamiques programmatiquement, sans concaténation de chaînes
FlywayOutil de migration de schéma BD — versioning des scripts SQL avec suivi d'exécution et détection de modifications
JNDIJava Naming and Directory Interface — registre permettant de localiser les ressources (DataSource, JMS) par leur nom logique
DataSourcePool de connexions JDBC géré par le serveur d'application — plus performant que des connexions directes unitaires
JTAJakarta Transactions API — API standard pour les transactions distribuées dans Jakarta EE
