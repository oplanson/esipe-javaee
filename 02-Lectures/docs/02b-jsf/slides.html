🏗️ Architecture JSF et Cycle de vie

JSF (JavaServer Faces) est un framework MVC orienté composants pour la construction d'interfaces utilisateur web en Java EE/Jakarta EE.

Les 6 phases du cycle de vie JSF :

  1. Restore View — reconstruit ou crée l'arbre de composants (UIViewRoot) pour la requête courante
  2. Apply Request Values — chaque composant extrait et stocke sa valeur depuis les paramètres de la requête
  3. Process Validations — les validateurs et convertisseurs sont exécutés sur les valeurs soumises ; les erreurs sont enregistrées
  4. Update Model Values — les valeurs validées sont propagées vers les propriétés des Managed Beans via les ValueExpressions
  5. Invoke Application — les action listeners et les méthodes d'action (ex : commandButton) sont invoqués
  6. Render Response — la vue est rendue (HTML généré) et envoyée au navigateur

Court-circuit : si des erreurs de validation surviennent en phase 3, le cycle saute directement à la phase 6 (Render Response) pour afficher les messages d'erreur.

🫘 Managed Beans avec CDI

Dans JSF moderne (Jakarta EE 9+), les Managed Beans sont des beans CDI annotés avec @Named pour les rendre accessibles depuis l'Expression Language.

Scopes des beans CDI :

  • @RequestScoped — bean créé pour chaque requête HTTP, détruit à la fin de la requête. Idéal pour les actions ponctuelles.
  • @ViewScoped (jakarta.faces.view.ViewScoped) — bean vivant tant que l'utilisateur reste sur la même vue JSF. Parfait pour les formulaires avec AJAX.
  • @SessionScoped — bean lié à la session HTTP de l'utilisateur. Pour les données persistant entre les pages (ex : panier, utilisateur connecté).
  • @ApplicationScoped — une seule instance partagée par toute l'application. Pour les caches et données globales.
  • @Dependent (défaut CDI) — le bean a le même scope que le bean qui l'injecte.

Annotation @Named :

@Named("clientBean") expose le bean sous le nom clientBean dans l'EL. Sans valeur, le nom dérivé de la classe est utilisé (ex : ClientBean → clientBean).

java 
@Named
@RequestScoped
public class ClientBean {
    @Inject
    private ClientService clientService;
    // accessible via #{clientBean.name}
}
📄 Facelets et Templates

Facelets est le moteur de templating officiel de JSF depuis JSF 2.0, remplaçant définitivement JSP. Les fichiers Facelets ont l'extension .xhtml.

Avantages de Facelets sur JSP :

  • Syntaxe XML stricte — les pages sont du HTML5 valide consultable directement dans un navigateur
  • Héritage de templates via ui:composition, ui:define, ui:insert
  • Meilleure intégration avec l'Expression Language (EL)
  • Pas de compilation séparée nécessaire

Tags principaux pour le templating :

  • ui:composition template="..." — déclare qu'une page utilise un template et délimite le contenu à inclure
  • ui:define name="..." — dans une page cliente, définit le contenu d'une zone du template
  • ui:insert name="..." — dans le template, marque l'emplacement où le contenu d'une page sera inséré
  • ui:include src="..." — inclut un fragment Facelets réutilisable
  • ui:repeat — itère sur une collection (alternative à h:dataTable)
🧩 Composants JSF Core

JSF fournit une riche bibliothèque de composants d'interface répartis dans deux espaces de noms principaux : h: (HTML) et f: (Core).

Composants de saisie et affichage :

  • h:inputText — champ de saisie texte, lié à une propriété via value="#{bean.prop}"
  • h:inputSecret — champ mot de passe
  • h:inputTextarea — zone de texte multiligne
  • h:outputLabel — étiquette liée à un composant via for="componentId"
  • h:outputText — affichage d'une valeur avec encodage HTML automatique
  • h:message — affiche les messages d'erreur pour un composant identifié par for
  • h:messages — affiche tous les messages JSF de la page

Composants d'action et navigation :

  • h:commandButton — bouton de soumission de formulaire, déclenche une action ou un action listener
  • h:commandLink — lien hypertexte déclenchant une action
  • h:form — formulaire HTML, obligatoire pour tout composant interactif JSF

Composants de liste :

  • h:dataTable — tableau HTML généré dynamiquement depuis une collection
  • h:selectOneMenu — liste déroulante à sélection unique
  • h:selectManyCheckbox — cases à cocher à sélection multiple
✅ Validation et Converters

JSF intègre un mécanisme de validation et de conversion qui s'exécute en phase 3 du cycle de vie. En cas d'erreur, le cycle court-circuite vers la phase 6.

Validateurs intégrés :

  • f:validateRequired — vérifie que le champ n'est pas vide
  • f:validateLength — contrôle la longueur minimale et/ou maximale d'une chaîne
  • f:validateLongRange — valide qu'un nombre entier est dans un intervalle donné
  • f:validateDoubleRange — valide un nombre décimal dans un intervalle
  • f:validateRegex — valide une chaîne par rapport à une expression régulière

Validateurs personnalisés :

Créer une classe annotée @FacesValidator("id") implémentant jakarta.faces.validator.Validator et sa méthode validate(). Lancer une ValidatorException avec un FacesMessage en cas d'erreur.

Converters :

  • f:convertNumber — conversion de nombres avec format, locale et type (number, currency, percent)
  • f:convertDateTime — conversion de dates et heures avec pattern et timezone
  • Converters personnalisés via @FacesConverter implémentant Converter<T>
xhtml 
<h:inputText id="email" value="#{clientBean.email}">
    <f:validateRequired/>
    <f:validateRegex pattern="^[A-Za-z0-9+_.-]+@(.+)$"/>
</h:inputText>
<h:message for="email" styleClass="error-msg"/>
⚡ AJAX avec JSF

JSF intègre nativement le support AJAX via le composant f:ajax, sans nécessiter de bibliothèque JavaScript externe. Les requêtes partielles mettent à jour uniquement une portion de la page.

Attributs clés de f:ajax :

  • execute — liste des IDs de composants dont les valeurs sont soumises lors de la requête AJAX. @form soumet tout le formulaire, @this seulement le composant courant.
  • render — liste des IDs de composants à re-rendre dans la réponse AJAX. @all re-rend toute la page.
  • event — événement DOM déclencheur (ex : click, change, keyup, blur). Par défaut : action pour les boutons, valueChange pour les inputs.
  • listener — méthode bean à invoquer en plus de l'action normale (signature : void method(AjaxBehaviorEvent))
  • onevent — callback JavaScript exécuté à chaque étape de la requête AJAX
xhtml 
<h:commandButton value="Rechercher" action="#{clientBean.search}">
    <f:ajax execute="@form" render="resultPanel" event="click"/>
</h:commandButton>

<h:panelGroup id="resultPanel">
    <!-- contenu mis à jour par AJAX -->
</h:panelGroup>
🧭 Navigation Rules

JSF gère la navigation entre vues en résolvant la valeur retournée par une méthode d'action (outcome).

Navigation implicite (JSF 2.0+) :

Par défaut, si une méthode retourne la chaîne "clients", JSF cherche la vue /clients.xhtml. C'est la méthode recommandée — simple et sans configuration XML.

  • Retourner null ou void — reste sur la vue courante
  • Retourner "clients?faces-redirect=true" — redirige (pattern PRG)
  • Retourner "clients" — forward interne vers /clients.xhtml

Navigation explicite (faces-config.xml) :

Définie dans /WEB-INF/faces-config.xml — utile pour des règles complexes ou conditionnelles qui ne sont pas facilement exprimables en navigation implicite.

Redirect vs Forward :

  • Forward (défaut) — le serveur transmet la requête en interne, l'URL navigateur ne change pas
  • Redirect — une réponse 302 est envoyée, le navigateur effectue une nouvelle requête GET — l'URL change
💡 Bonnes pratiques JSF

Architecture et conception :

  • Éviter la logique métier dans les beans — les Managed Beans sont des contrôleurs MVC ; déléguer la logique aux services CDI injectés
  • Utiliser les scopes CDI correctement — préférer @RequestScoped ou @ViewScoped par défaut ; éviter @SessionScoped pour les données non liées à la session utilisateur
  • Préférer la navigation implicite — éviter les règles faces-config.xml sauf nécessité absolue
  • Éviter le scope session profond — stocker en session uniquement ce qui est strictement nécessaire ; préférer les paramètres de vue (@ViewScoped)

Performance et maintenabilité :

  • Utiliser f:ajax pour les mises à jour partielles plutôt que de recharger la page entière
  • Organiser les vues avec des templates Facelets (header, footer, layout commun)
  • Utiliser h:outputText plutôt que #{...} direct pour l'encodage HTML automatique (prévention XSS)
  • Activer le mode développement JSF (ProjectStage.Development) pendant le développement pour des messages d'erreur détaillés
  • Désactiver le ViewState côté client en production si non nécessaire, ou utiliser le ViewState côté serveur
