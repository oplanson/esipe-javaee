FonctionnalitéEJB (Session Bean)CDI Bean
Transactions déclaratives✅ Nativement intégrées (CMT)Via @Transactional (intercepteur CDI)
Clustering & passivation✅ Stateful beans passivables, clustering natif❌ Non supporté nativement
Accès distant (Remote)✅ Via interface @Remote❌ Local uniquement
Sécurité @RolesAllowed✅ Intégrée au conteneurVia intercepteur personnalisé
Timer Service✅ @Schedule, @Timeout natifs❌ Non disponible

Complexité⚠️ Plus lourde — spécification dédiée✅ Légère, POJO orienté

Patterns EJB courants

Nom du patternDescriptionQuand l'utiliser
Service FacadeUn EJB Stateless expose une API simplifiée masquant la complexité des sous-systèmes internes (JPA, JMS, autres EJBs)Quand les clients (REST, JSF) ne doivent pas connaître le détail des opérations internes
Session FacadeUn Stateful EJB orchestre plusieurs opérations sur plusieurs appels pour un même client, maintenant l'état intermédiaireWorkflows en plusieurs étapes nécessitant un contexte conservé entre les requêtes
DAO PatternUn EJB Stateless encapsule toutes les opérations CRUD sur une entité JPA, séparant la logique d'accès aux données de la logique métierToujours — pour isoler la couche de persistance et faciliter les tests unitaires

Glossaire

TermeDéfinition
EJBEnterprise Java Beans — composants serveur Java gérés par le conteneur Jakarta EE, encapsulant la logique métier et délégant les services transversaux (transactions, sécurité, timers) au conteneur
@StatelessAnnotation déclarant un Session Bean sans état conversationnel — poolé par le conteneur, idéal pour les services métier haute performance
@StatefulAnnotation déclarant un Session Bean conservant l'état par client — une instance dédiée par conversation, passivable par le conteneur
@SingletonAnnotation déclarant un Session Bean dont une seule instance existe dans toute l'application — nécessite une gestion explicite de la concurrence
@MessageDrivenAnnotation déclarant un Message-Driven Bean — composant asynchrone déclenché par l'arrivée de messages JMS dans une queue ou un topic
CMT / BMTContainer-Managed Transactions / Bean-Managed Transactions — deux modes de gestion des transactions EJB. CMT délègue au conteneur (via @TransactionAttribute), BMT gère manuellement via UserTransaction
@EJBAnnotation d'injection permettant d'injecter une référence vers un autre EJB dans un composant Jakarta EE — analogue à @Inject mais spécifique aux EJBs
Timer ServiceService EJB permettant de planifier l'exécution de méthodes à des moments définis — via @Schedule (automatique, style cron) ou via l'API programmatique TimerService
Activation ConfigurationEnsemble de propriétés @ActivationConfigProperty configurant un MDB — type de destination, nom JNDI, filtre de messages, mode d'acquittement
